# 审阅报告使用说明（"我的定稿"工作流）

> 2026-09-18 起，每份审阅报告在"修改后的内容"与"修改原因或描述"之间新增第 4 列
> **「我的定稿」**：一个可编辑文本框，默认填好建议稿的纯文本，你直接在上面改。

## 你要做的只有三步

1. **打开页面**：浏览器访问 `http://127.0.0.1:8734/`，点开要审的那份报告。
2. **编辑定稿**：在"我的定稿"框里调整文字。每次改动自动保存（localStorage）并自动
   同步落盘到 `0917/finals/<章节名>.json`——不需要点任何保存/导出按钮。
   "我的选择"下拉和备注照常可用，同样会一起同步。
3. **告诉 Claude**：审完哪份，在对话里说一句（如"第八章我审完了"），
   Claude 读 `finals/` 里你确认过的定稿去替换 `chapters/` 原文。

页面工具栏上有同步状态：`定稿已同步 时间` 表示已落盘；`未连接同步服务` 表示服务
没开（编辑不会丢，仍在本页保存，服务恢复后刷新页面即补同步）。

## 服务没开时怎么启动

双击 `0917/启动审阅服务.command`（或终端跑 `python3 scripts/review_sync_server.py`），
然后从 `http://127.0.0.1:8734/` 打开页面。

## 注意

- **始终从 `http://127.0.0.1:8734/` 打开页面**（不要双击 html 文件打开），保证
  localStorage 一致、同步不中断。误用 file:// 打开也能同步，但本地刷新记忆会分开。
- 刷新、关页面、甚至重启浏览器都不丢：重新打开会恢复你改过的定稿。
- 序言页的"清除"按钮只清"我的选择"和备注，**不会清你的定稿**（防误触）。
- 打印/导出 PDF 时定稿列会一起印出。
- 原始未改动版本备份在仓库根 `.backup-0917-20260918/`。

## 维护备注（给 Claude）

- 三套模板（A=序言带 review-data JSON；B=第4–10章；C=第2、3章）由
  `scripts/patch_review_html.py` 统一打补丁，可幂等重跑。
- 回归测试：`python3 scripts/test_review_pages.py`（需服务在跑）。
- `finals/<章节名>.json` 每行字段：`final`（用户定稿）/ `suggested`（建议稿纯文本）/
  `old`（原文纯文本）/ `decision` / `note` / `level` / `section` / `search` / `link`。
  替换章节原文时以 `final` 为准，`old`/`search`/`link` 用于定位核对。
