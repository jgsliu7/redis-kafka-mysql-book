接口概念稳定不等于结构和架构始终未变

第 248 行

回看这三个软件最成功的接口：Redis 的 robj（type/encoding 分离）、MySQL 的 Handler API（行操作契约）、Kafka 的 Log 格式（顺序追加、按偏移量寻址）。这三者都谈不上优雅。robj 用一个联合体加指针覆盖了所有类型，Handler API 的方法签名又多又碎，Kafka 的 Log 是最朴素的"一段一段的文件"。但它们有一个共同点：多年不变。robj 从 Redis 早期到现在核心结构没动过。Handler API 自 MySQL 5.x 插件化以来接口形态稳定。Kafka 的日志格式虽然有版本演进，但"顺序追加 + 偏移量寻址"的根基没变。

第 280 行

这五条合起来看，三个软件都没重写过架构。Redis 从一个缓存工具发展为支持多种数据结构、Function、Cluster 的多模数据库，核心层（robj、命令表）始终没动。MySQL 和 Kafka 走的是同一条路：核心接口（Handler API、Log 抽象）十几年不动，新功能都加在外围。

“多年不变”“核心结构没动过”“十几年不动”“新功能都加在外围”把稳定的抽象原则扩大成实现和架构没有变化；robj 的“联合体加指针”描述也需要对照结构定义。
