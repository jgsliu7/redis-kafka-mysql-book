# 读者086 · 哨兵人
身份：Redis 哨兵生产用户，6年，爱好：飞钓
主读：第 9 章

## 五个问题

1. 【9.3|技术事实】半同步一节写"副本 I/O 线程把事件写入 relay log 并落盘后即回 ACK"——这个"落盘"我存疑。我查到的说法是 ACK 在事件写入 relay log 后即发，是否 fsync 由 `sync_relay_log`（默认 10000）控制；若副本在 ACK 后、fsync 前整机掉电，ACK 过的事务照样丢。半同步保证的是"到了副本的 relay log 文件"，不是"副本已持久化"，"落盘"二字读起来像后者，请作者核实措辞并给依据。

2. 【9.2|深度广度】"故障转移的数据语义"整节只有四句话就收场了，而这是我这种做过 failover 复盘的人最想读的一段。最关键的一层没讲：丢了多少怎么算。MySQL 复盘可以拿两边 GTID 集合一减（GTID_SUBTRACT），丢了哪些事务清清楚楚；Redis 事后没有任何对账工具，老主一旦以副本身份被新主覆盖，分叉那段写的证据就没了，只能靠故障前抓的 `master_repl_offset` 差值估。这个"丢失可审计性"的维度在 9.5 对比表里也完全缺席。

3. 【第9章导读/9.7|逻辑论证】导读用亲身事故立题——"删缓存和写数据库的先后顺序在不同代码路径里不一致"，这是双写顺序问题；9.7 给的答案却是"数据库是正本、缓存是可重建的派生数据"，这回答的是"冲突时信谁"。正本观念再清楚，那起事故照样发生，根因是失效路径不统一。开头的痛点和结尾的答案对不上，是我理解偏了，还是本来就想换个问题答？

4. 【图9-4|图示】格子里标"cmd B off=330"，下面又写"replica offset = 330（断线前同步到 cmd B）""请求从 331 开始"。如果 330 是 cmd B 的起始字节，同步完 B 的位点应该是 380 而不是 330；我只能倒推出 off 标的是"该命令写入后的累计字节数"（末尾位置）才自洽，但图里从头到尾没说。第一次读的人几乎必然按"起点"理解然后算错，我盯着这张图多算了两遍。

5. 【9.2|逻辑论证】级联复制一节说"对于读副本来说这点延迟通常可接受"——不认同这句的轻描淡写。生产上级联是刻意设计：只有业务明确声明"允许陈旧"的读才敢路由到二级副本，这是设计前提，不是读副本的天然属性。而且级联真正贵的代价不在延迟累积，在爆炸半径：中间一级副本故障，下游整棵子树变孤儿要人工重新指主，Sentinel 不会自动重排树——故障恰好发生在全树掉线时。延迟累积反而是三种代价里最轻的。

## 五个建议

1. 【9.6 反模式|案例示例】把"复制风暴"的正反馈闭环写进反模式：慢副本因 output buffer 超限被断开 → 重连 → backlog 盖不住 → 全量同步 → fork/COW/出口带宽再承压 → 更容易再超限。现有"续传信息不足导致副本重建"只写了单次重建，没写这个循环；顺带点一句 `client-output-buffer-limit replica` 和 `repl-backlog-size` 要一起调的生产套路。我带新人的第一课就是防这个循环，光调大 backlog 防不住。

2. 【9.2|深度广度】把"故障转移的数据语义"扩成真正一小节，纳入三个上过生产马上会问的点：Sentinel 的 `parallel-syncs`（控制 failover 后多少副本同时对新主重同步，是同步主题里少见的拓扑节流旋钮）；`min-replicas-to-write` 在新主晋升后、其余副本重新 ACK 前会拒绝写入的空窗；老主重连被覆盖时"丢失证据随之消失"的复盘注意点。

3. 【9.7（或 9.3 末）|案例示例】给导读的缓存事故一个真正的收口：加一小段写失效顺序（先写库后删缓存、延迟双删）和"用 binlog 驱动缓存失效"（canal/Debezium 一类 CDC）。后者正好复用 9.3 的主题"binlog 作为传播单元"，把同步的视野从"副本"扩到"派生系统"，导读的痛点才算被本章机制接住，首尾就通了。

4. 【9.5|深度广度】表 9-1 建议加一行"确认不满足时的行为"：MySQL 半同步超时降级继续接受写、Kafka ISR 不足拒绝写、Redis 门槛不到拒绝写。9.4 里作者那句"写路径碰钱和库存时，我站 Kafka 这边"是全章我最想抄进方案评审的话，值得把这层降级语义提炼进对比表——评审会上被问得最多的就是"降级之后系统还写不写"。

5. 【图9-4|图示】给 offset 一个明确的语义标注：格子标签改成"cmd B（末尾累计 330）"，或图注注明"off 表示该命令写入后复制流的累计字节数，PSYNC 请求的是下一个字节（331）"。另外图内用"replica offset"、9.2 正文用 `slave_repl_offset`，两处口径统一一下，读者对照时不用自己翻译。
