## 五个问题

1. 【1.4.3|术语使用】本节先写"借 B+ 树、WAL、状态机复制、CAP 等主题讨论架构取舍"，几行之后才立下"全书术语首次出现时中英对照标注"的约定，而"状态机复制（state machine replication）"和"CAP"正是全书首现，既无英文对照也无一句解释。没读过 Brewer 定理与复制状态机文献的读者（也就是 1.4.1 里声明不假设的读者）到这句只能跳过，作者自己立的规矩在同一个小节里就被违反了。

2. 【1.1.2|技术事实】"这种设计影响了后面的 Pulsar、各种事件溯源（Event Sourcing）方案和 CDC 管道等一大批系统"——事件溯源作为模式（Fowler 2005 年的文章）比 Kafka（2011 开源）早约六年，CDC 概念（Oracle 变更捕获一类）更早，"影响了后面的"读起来像因果倒置。Kafka 让这些早已提出的模式大规模落地是一回事，"影响了方案本身"是另一回事，此处表述经不起抠时间线。

3. 【1.1.2|其他】"LinkedIn 2014 年公开的基准里，3 台廉价机测到约 200 万次写入/秒（Kafka 0.8.1、100 字节消息）"没有任何可查的出处：不是论文也不是工程博客链接，全章也没有脚注或指向附录参考文献的机制。我的第一反应是去读原文，却无从查起；也无法据此判断 0.8.1 时代的基准数字与本书 3.x 基线之间差了多少代。

4. 【1.2.4 表 1-1（及图 1-1）|逻辑论证】表 1-1"关键取舍/可舍弃"一栏写 MySQL 舍弃"写性能"，图 1-1 同样写"舍弃：写入性能"，但正文（1.1.3 与 1.2.2）列出的代价是"写放大、事务开销、调优门槛"，且提交变慢被明确限定在"每次提交都刷盘的配置下"才成立。InnoDB 并非无条件放弃写性能（组提交等也在优化写路径），表格与图把正文的条件命题简化成了无条件断言，三处口径不一致。

5. 【1.1.1|逻辑论证】"绝大多数后端系统，拆到最底层，都绕不开三类基础能力"这个分类的完备性存疑：协调与元数据类基础设施（ZooKeeper、etcd）既不落"快速读写"也不落"可靠存储"或"异步流转"，而书里 1.3.2 就要用共识（KRaft）、1.2.2 已提到基于共识的 MGR——"控制面"这一层被三分类整体漏掉。它是被有意排除在"数据面基础设施"之外，还是分类本身不完备，希望有一句交代，否则完备性断言站不住。

## 五个建议

1. 【1.2.4 图 1-2|图示】雷达图配了精确到个位的 0-5 评分表（Redis 低延迟 5、Kafka 强一致 3、Redis 强一致 2……），却没有给出任何评分准则：强一致上一个 3 和一个 2 的差别是什么？无 rubric 的数字制造虚假精度，读过 OSDI/Benchmark 类论文的读者会本能地不信任。建议要么给每档写清界定依据（如"3 = 可配置持久性 + 分区内有序，而非线性一致"），要么改用定性记号；图注"作者主观量级判断"之外，可再给一两个真实量纲锚点（如 P99 延迟量级、单分区吞吐）。

2. 【1.3.3|深度广度】"Kafka 把数据本身存成日志……不需要再把命令重放成另一套业务数据结构"——这正是复制状态机里状态机退化为恒等函数的特例，而 1.4.3 已把"状态机复制"列为全书主题。建议在这里加一小段或脚注，把 AOF 重放、redo 应用、Kafka offset 复放统一放进"重放日志以重建状态 vs 直接复制日志即数据"的框架：读过 Raft 的人会立刻对上 replicated log，没读过的人也提前拿到第 9 章的钥匙。

3. 【1.4.4|结构导航】路径 C 说"每章只重点看横向对比与架构启示"即可入门，但 1.4.2 又强调"章与章之间是递进的关系……前面的结论是后面讨论的输入"，且第 2 章被点名为"后面所有讨论的输入"。两处合起来读是矛盾的：强依赖链之下不存在无代价的跳读。建议为路径 B/C 给出每章的最小前置小节清单（或在每章导读里标注"依赖：2.x"），把冲突化解成可执行的跳读地图。

4. 【1.2.1|深度广度】1.1.1 和 1.2.1 两次把"分布式锁"列为 Redis 典型场景，却没有任何正确性限定。Redis 锁的可靠性是有前提的（单实例的租约过期与故障切换丢锁问题、fencing token 的必要性，社区有著名争论），建议加一句脚注或指向本书后续相应章节。否则像我这样没碰过生产的学生，很容易把 SET NX 直接当成可靠的分布式锁带进自己的项目。

5. 【1.4.3|其他】建议建立全书的引用机制并从第 1 章开始示范：所有基准数字与版本时间线（"2014 年 200 万写/秒""8.0 于 2026 年 4 月转入 Sustaining Support""Kafka 3.3 KRaft 生产可用"）用脚注编号挂到附录参考文献，读者可核对一手来源；同时补上 CAP 与状态机复制的首现标注和一句话定义，兑现本节自己立下的术语约定。对一本强调"理解设计决策"的书，可溯源是可信度的下限。
