# 读者057 · 被挖矿
身份：中小公司运维，5年，爱好：网游
主读：第 6 章

## 五个问题
1. 【导读|案例示例】导读把公网 6379 被扫的后果写成"把我们的实例当成了免费缓存"，而 6.2 自己承认"历史上未授权 Redis 写 SSH 公钥、写定时任务导致远程代码执行（RCE）的案例非常多见"——两处威胁强度对不上。作为真被挖过矿的人，生产环境 6379 裸奔的标准结局是 crontab 被写进挖矿脚本、CPU 打满、游戏玩家集体掉线，导读这个"温和版"会让读者低估风险。
2. 【6.2|深度广度】6.2 说"6.0 之前的 Redis 只有一个 requirepass 全局密码"，但 6.0 之后 requirepass 并没有消失，而是被映射为 default 用户的密码——存量配置升级到 6.x/7.x 后还算不算数，正是我们这些老配置一把梭的中小公司最关心的事，书里一句没交代。
3. 【6.3|读不懂】protected-mode 那段"是否绑定全部网卡不是这一判断的条件"读完更糊涂了：bind 0.0.0.0 加给 default 设了密码，远程连接到底放不放行？只想做加固的运维需要的是一张"bind/密码/保护模式"三条件的判定表，而不是这句否定式说明。
4. 【6.2|读不懂】KRaft 那段连发 3.5.0/3.5.1/3.6.0 三个版本号，又区分"Broker 到 Controller 的 SCRAM 支持"与"Controller 之间的共识连接"两条路径，既没有图也没有例子，更没给 KIP 或 JIRA 编号可查。我对 Kafka 只到会部署的程度，这段完全是黑洞，只能硬着头皮跳过。
5. 【6.2|图示】图 6-2 图注"内部 SASL_SSL、外部 SASL_SSL、控制面 KRaft 三条路径并行"——前两条协议同名，第三条写的却是部署组件名而不是协议，三条并列在信息上不对称；光读图注分不清三条路径的本质差别是证书域、端口还是信任边界。

## 五个建议
1. 【导读|案例示例】把导读案例升级成完整攻击链：未授权访问 → CONFIG SET dir/dbfilename → 写 /var/spool/cron 或 ~/.ssh/authorized_keys → 挖矿木马落地。一句话的"RCE 案例非常多见"没有画面感，画出这条链才能让没中过招的读者记住"当天就会被扫到"意味着什么。
2. 【6.5|深度广度】审计一节给 Redis 补上取证视角的硬数字：ACL LOG 默认只保留 128 条、SLOWLOG 默认阈值 10ms/长度 128。我被挖矿后第一件事就是回查"谁写的 crontab"，书里只说"弱"不给数字，我没法评估该外挂什么——日志采集还是 MONITOR 短时抓现场。
3. 【6.6|结构导航】"从姿态对比到生产底线"里 MySQL 有 mysql_secure_installation、connection_control，Kafka 有评审三重点，Redis 却没有等价的落地清单。建议补一组 5 分钟自查命令：CONFIG GET protected-mode、ACL LIST、redis-cli --scan 抽查异常键、顺手检查 crontab 和 authorized_keys——这才叫对称的"生产底线"。
4. 【序言|其他】序言把读者定位为"有两年以上开发经验的后端工程师、软件架构师以及技术负责人"，漏了运维/SRE。第 6 章的生产底线、监听器配置矩阵、TDE 密钥管理全是我每天在碰的东西，这本书对运维的价值不比对开发低，建议把运维写进目标读者。
5. 【6.4|深度广度】Redis 加密一节讲 6.0 前的替代方案只提 stunnel 和 SSH 隧道，但中小公司 6.0 前最普遍的兜底其实是 bind 127.0.0.1/内网地址加防火墙白名单——网络层隔离。建议把它作为加密的前置选项写进 6.4，正好与 6.7 启示二"纵深防御第一层是网络隔离"呼应。
