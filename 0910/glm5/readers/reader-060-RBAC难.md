# 读者060 · RBAC难
身份：普通后端，5年，爱好：电影
主读：第 6 章

## 五个问题

1. 【6.3|逻辑论证】图 6-4 和正文都说 MySQL 权限"逐层收窄、命中即停"，这个"收窄"对权限新手有误导：MySQL 没有 DENY，全局层命中 SELECT 之后列级根本无法再收紧，真实语义是"从粗到细找到第一个授予权限的层级就停"，而不是越往下越严。我踩过的坑正是想用列级权限去限制一个已有全局 SELECT 的账号，发现完全不生效——书里不点破这层语义，像我这样搞不清权限模型的读者读完反而会自信地配错。

2. 【6.2|读不懂】Kafka 一节"这与 Controller 之间的共识连接不是同一条路径。后者在 3.5.1、3.6.0 曾出现用 SCRAM 启动集群失败的问题"这段我读了三遍还是糊的：Broker→Controller 的认证和 Controller↔Controller 的共识连接各能用什么机制、哪条路径会失败、生产上该怎么配，全靠一句嵌套长句脑内解析。图 6-2 只画了监听器三层，没把这两条控制面路径分开画。

3. 【6.3|表达可读】"6.2 起，通道（channel）权限也独立出来"——我第一眼读成"本章 6.2 小节起"，愣了几秒才反应过来是 Redis 6.2 版本。版本号撞上本章小节号，循序渐进的读者会被绊一下，应写"Redis 6.2 起"。

4. 【6.3|深度广度】我是带着"ACL 和 RBAC 到底差在哪、我的系统什么时候该上角色"这个问题进本章的，三家各给了一句取舍理由（Redis 内核要轻、MySQL 兼容优先、Kafka 主体是服务），但没有任何一处正面讲"角色这层抽象换来的到底是什么"（权限画像复用、批量收权、按画像审计归因）。读完我对三家的"是什么"清楚了，对自己的系统"该不该上 RBAC"还是没答案。

5. 【6.3|表达可读】protected-mode 一段里"是否绑定全部网卡不是这一判断的条件"这句否定式补丁，让我下意识往回翻找"哪里说过绑定网卡"——前文并没有，读者会怀疑自己漏读了什么，这更像改稿时纠正旧版的痕迹泄漏进了正文；且"保护模式开启且 default 用户带 nopass 标记时拒绝非本地连接"三重条件堆在一句里，弱读者要拆解半天。

## 五个建议

1. 【6.3|案例示例】给"逐层收窄"补一个反例案例：对已有全局 SELECT 的账号尝试在列级收回某一列、发现不生效，让读者亲眼看到"上层命中、下层失效、没有 DENY"。这一条是权限苦手最需要的防坑案例，比正面的流程图更值钱。

2. 【6.2|图示】在图 6-2 里（或旁边加一张小图）把"Broker→Controller"和"Controller↔Controller 共识"两条路径分别画出，各自标注可用机制（SCRAM 需 3.5.0+、mTLS）和已知踩坑版本。两条线配两句话，胜过现在这段嵌套长句。

3. 【6.3|案例示例】建议在 6.6 横向对比之后加一个"同一场景三家对照"：比如"订单服务 + 数据分析两个身份访问同一套数据"，分别用 Redis 键模式加命令类别、MySQL 角色加列权限、Kafka 前缀 ACL 各配一遍。像电影的三线叙事，同一安全意图在三种模型下的表达差异一对照就懂，比表格列"是什么"更能落到"怎么用"。

4. 【6.3|表达可读】"6.2 起"这类裸版本号改成"Redis 6.2 起"，并排查同章版本号与本章小节号撞车的句子（对照"8.0 才补齐""6.0 引入"等写法统一为带软件名的版本号）。

5. 【6.6|表达可读】表 6-1 的"初始认证配置"行和"默认策略"行都在说"默认"，但前者是出厂认证状态、后者是启用授权器之后的授权策略，是两个独立开关。建议行名改成"出厂认证状态""启用授权器后的默认授权策略"或加脚注，免得读者把两个"默认"读成同一个开关——我就误读成"Kafka 又不认证又默认拒绝，那还有谁能连上"。
