# 读者021 · 值班狗

身份：SRE，8年，爱好：手冲咖啡
主读：第 3 章

（阅读习惯说明：事故驱动阅读。导读里那句"凌晨三点 kill -9"直接把我按住了，第 3 章我是逐段读的，重点盯关闭流程与恢复语义，两张关闭流程图（图 3-3、图 3-6）的 SVG 也翻了。）

## 五个问题

1. 【3.4|技术事实】启动阶段 3 说"每个分区都要单独校验、单独重建索引，没有批量恢复这种捷径"，读起来像万分区集群每次重启都得逐段全量校验。但受控关闭后重启，Broker 会写恢复位点检查点（恢复点已在日志末尾），恢复实际基本跳过；只有崩溃后的重启才付全量校验的成本。我滚动重启过上万分区的集群，干净重启明显比崩溃重启快得多。书中不区分这两种情形，到底哪种对？

2. 【3.2|逻辑论证】关闭第一步"直接杀掉 RDB/AOF 重写子进程——优雅关闭优先缩短关闭耗时"，可 3.4 容器化一节又明确：默认配置（出厂就带 save 点）下 SIGTERM 关闭会同步做一次全量阻塞 SAVE。那在默认路径上，把快完成的 bgsave 杀掉、进度作废、再从头做一次更久的阻塞 SAVE，"优先缩短关闭耗时"说不通。为什么不等子进程做完？书里没有解释这条取舍。

3. 【3.4|读不懂】preStop 建议"先触发 BGSAVE，确认本次快照成功完成后再执行 SHUTDOWN NOSAVE"，但书自己也强调 BGSAVE 返回成功只表示后台保存已启动。那"确认完成"在 hook 里到底拿什么信号判断？（我实操是轮询 LASTSAVE 时间戳变化，或等 INFO persistence 里 rdb_bgsave_in_progress=0。）照书写会直接卡在"确认"这一步，这段缺一个可落地的等待办法。

4. 【3.3|深度广度】表 3-1 把 innodb_fast_shutdown=2 描述为"只刷 redo 不刷数据页，近乎 kill -9"，但档位 2 下 server 层（binlog 正常收尾、连接正常断开）走的仍是优雅关闭，真正模拟崩溃的只是 InnoDB 层；撕裂 binlog 事件组、坑掉从库的是 kill -9 的独有风险。"近乎"二字近到什么程度，表格无法判断——我处理过主从断连事故，很在意这个差别。

5. 【3.2|技术事实】"几十 GB 的实例从加载到就绪可能要几分钟，这期间整个实例不可用"——但按启动四阶段（图 3-2），监听端口在基础设施段就打开了，早于数据恢复段。我碰到的实际表现是 TCP 能建连、命令回 -LOADING 错误（而不是 connection refused）。"不可用"到底是拒绝连接还是连得上不响应？这直接决定 readiness 探针和客户端重试怎么配，书里该说破。

## 五个建议

1. 【3.4|结构导航】"容器化环境下的生命周期"小节讲的是 K8s 通用约束加三家各自的 grace period 实践，内容横跨 Redis/MySQL/Kafka，却挂在"3.4 Kafka 的做法"名下。建议提成独立小节（放在横向对比之前），横向对比顺延；现在这样，读 Redis/MySQL 部分的读者容易漏掉这节全书最实用的内容。

2. 【3.3|案例示例】"关闭慢的常见根因"四条清单很好，建议每条配一条当场可执行的观察手段：脏页看 Innodb_buffer_pool_pages_dirty 的下降速率、长事务查 information_schema.innodb_trx 的 trx_started、复制线程看 replica 状态、回滚进度 PROCESSLIST 是看不到的。只给"对着四类根因看 SHOW PROCESSLIST"一句，实际定位不了回滚卡点。

3. 【3.4|深度广度】受控关闭一节说差别在"客户端感受"，但只有"抖动窗口小得多"一句。建议补一段客户端侧视角：Leader 迁移期间 producer 的元数据刷新与重试、consumer 的 rebalance、退化为普通关闭时客户端的典型报错（NOT_LEADER_FOR_PARTITION 之类）。SRE 看 Broker 重启，第一眼盯的就是这些指标和告警。

4. 【3.6|案例示例】首尾呼应的订单事故（导读埋、3.6 收）是全书最抓人的钩子，建议补上复盘必需的配置细节：当时 appendfsync 是 everysec 还是 always？"十几条订单"是怎么从丢失窗口推算出来的？事故驱动阅读的读者第一件事就是核对配置，补上这几笔案例可信度翻倍。

5. 【3.2|图示】正文说 7.0 起关闭前多一道"等落后副本追平（上限 shutdown-timeout 默认 10 秒）"，但图 3-3 从"关闭触发"直接跳到第①步，没画这道等待。这 10 秒恰恰是 grace period 预算里的第一项，做停机预算的人按图算会漏掉它，建议在图上补这个分支（含超时旁路）。
