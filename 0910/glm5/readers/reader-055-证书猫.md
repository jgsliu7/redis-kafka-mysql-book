# 读者055 · 证书猫
身份：TLS 运维自动化，6年，爱好：拍 vlog
主读：第 6 章

## 五个问题
1. 【6.2|深度广度】Kafka 认证一节把 TLS 严格限定为"加密"、认证全归 SASL（"对外采用 SASL_SSL"的写法尤其让我这种配 mTLS 的人别扭）：Kafka 的 SSL 监听器配 `ssl.client.auth=required` 时客户端证书本身就是认证，Principal 直接取证书 DN（可用 `ssl.principal.mapping.rules` 映射），不配任何 SASL 也能跑纯 mTLS。书中"认证=SASL、加密=TLS"的二分漏掉了这条一等公民路径，连带图 6-1"先 TLS 隧道、后认证"的接力模型在 mTLS 场景也不成立——认证发生在握手里，不是隧道之后的一段。

2. 【6.3|技术事实】protected-mode 那句"是否绑定全部网卡不是这一判断的条件"与官方 redis.conf 注释对不上——注释里 protected mode 生效前提之一正是"没有用 bind 指令显式指定绑定地址"。书里断言得很干脆却没给出版本或源码出处，我拿这个条件做过加固核对，在这里停了很久不知道该信哪边。

3. 【6.4|逻辑论证】6.1 给存储加密立的威胁模型是"数据落盘后即使磁盘被盗也无法直接读取"，但 6.4 自己讲明社区版只有本地文件型 keyring_file——主密钥明文放在同一台机器上，整盘被盗时锁和钥匙一起到手，那个威胁模型只有企业版（Vault/KMS）才兑现。同章前后自拆，这段至少该先把两处口径对齐。

4. 【6.2|读不懂】"KRaft 控制面还要解决启动期凭证是否可用的问题"一整段：一段话里塞了 Broker 到 Controller 的 SCRAM、"与 Controller 之间的共识连接不是同一条路径"、"其约束来自具体路径和版本的实现"三种指代，而 Controller 间共识连接是什么要到第 7 章才展开。我反复读了三遍仍没法准确复述这条链路上谁在启动期拿不到凭证，只记住了 3.5.1/3.6.0 出过问题。

5. 【6.1|结构导航】6.1 把"复制与分布式协调：主从之间、Broker 之间也要互相认证"列为数据系统的三大特殊约束之一，但这条约束只有 Kafka 兑现了（inter-broker TLS 写了）；Redis 一节只讲面向客户端的 tls-port，`tls-replication`/`tls-cluster` 一个字没提，MySQL 复制连接要不要 TLS 也没讲。开头立的约束在小节里没了下文，开了头没收尾。

## 五个建议
1. 【6.4|深度广度】补一小节"证书生命周期运维"：三家换证书要不要重启、能否热加载（MySQL 有 `ALTER INSTANCE RELOAD TLS`，Kafka broker 支持监听 keystore 变更热加载，Redis 的情况如实写），再加"证书到期忘续引发整集群雪崩"这个 TLS 落地最常见的故障。现在全章关于证书轮转只有"证书按域独立签发与轮转"半句话，而这部分占生产 TLS 工作量的大头。

2. 【6.2|图示】图 6-2 标题把"内部 SASL_SSL、外部 SASL_SSL、控制面 KRaft"并列为三条路径——前两个是安全协议、第三个是共识模式，不是同一类标签，读者会误以为 KRaft 是某种加密方式；且内外都是 SASL_SSL 时"按网络域分级信任"到底级在哪（不同 CA？不同证书？），建议把信任差异直接画在图上。

3. 【6.2|案例示例】Kafka 监听器分层给一个完整可抄的配置样例（`listeners`/`advertised.listeners`/`listener.security.protocol.map` 三件套，双网络域各一条），并把文中点到的"advertised 主机名不属于客户端所在网络域"故障画成时序（客户端从 metadata 拿到错误地址、连接失败）。这是我见过最多的 Kafka 安全类工单，文字提了但读者照着配还是会踩。

4. 【6.4|术语使用】"记录层的对称加解密（AES-GCM 等 AEAD 套件）"一句里"记录层"（TLS record layer）和 AEAD 都没展开——连 ACL、SASL 这种词都给了中英对照，这里两个更冷门的术语反而裸奔，建议至少给 AEAD 一行解释（同时提供机密性与完整性的一类对称加密）。

5. 【6.5|深度广度】审计一节停在"现状都弱、生产靠外挂"，建议给三家各一行"最小可行审计"落地组合，并补两个量化事实让读者有体感：Redis ACL LOG 在内存里只保留约 128 条，不外接采集必丢；Kafka 把 `kafka.authorizer.logger` 开到 DEBUG 连放行也记，大集群日志量会非常可观。"外挂"这个结论才算落到可操作。
