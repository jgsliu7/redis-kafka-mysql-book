# 读者077 · Parquet
身份：大数据平台工程师，6年，爱好：自驾
主读：第 8 章

## 五个问题
1. 【8.4.3|深度广度】这一节讲 Batch 级压缩"2–6 倍、带宽与存储成本结构性下降"，但通篇没说压缩发生在哪一端：是生产者压好再发、Broker 原样落盘，还是 Broker 收到再压？这决定了 CPU 成本落在谁头上，也解释了为什么压缩边界要和批边界一起定义在协议层（生产者的攒批参数直接决定压缩比）。我带着这个问题读完 8.4.3 没找到答案，只能靠自己的运维经验脑补。
2. 【8.5.2|逻辑论证】"另一项代价是定长页的空间浪费：一页里哪怕只剩几行 100 字节的记录，也要占整整 16KB，半空的页在所难免"——这个归因我不认同：InnoDB 删除时有页合并（MERGE_THRESHOLD 默认 50%），半空页主要是 B+ 树分裂填充因子和批量删除后碎片的结果，是"原地改 + B 树组织"的代价而非"定长"本身，变长记录的组织同样会有半空块。定长页真正固有的空间代价是页头尾与槽的固定开销（16KB 里约 0.8%），书里把两件事混在一句里了。
3. 【8.3.3|技术事实】"不超过 40 字节的短 TEXT/BLOB 留在行内"——这个 40 字节阈值我在官方手册的行格式一节找不到对应表述（手册只写整行判定与 COMPACT 的 768 字节前缀），它更像源码级行为，建议标注出处；另外判据到底是"列内容实际长度 ≤40"还是"列定义长度"，对 BLOB 和 VARCHAR(10) 含义完全不同，书里没说清，我算不准自己的表会不会命中这条。
4. 【8.6.3|逻辑论证】8.3.3、8.4.4、8.6.3 三处把 InnoDB Page Directory 与 Kafka 稀疏索引并称"相近思路/同一手法"，"二分缩范围 + 局部顺扫"的共性我认同，但两者性质差别被抹平了：槽是随插入自适应增长的（每 4–8 条一槽）且是页格式的固有部分、不可分离；Kafka 的索引间隔是 `log.index.interval.bytes` 静态配置，而且索引文件删掉可以从 `.log` 重建（崩溃恢复时就是重建的）。一个是数据本体的一部分，一个是可再生的衍生结构，只讲共性不讲差异，读者容易把两者当成同一种东西去调优。
5. 【8.1.3|表达可读】关键数字框里 V0/V1 的主口径是"不含最外层 12 字节消息框"（14/22 字节，含外框 26/34 用括号补充），而 V2 的"每批元数据约 61 字节"却把 BaseOffset + BatchLength 这 12 字节外框算进去了（纯批头元数据是 49 字节）。我逐字节核过 61 的构成，数字本身没错，但两处口径相反且 V2 没做同样的标注，拿 61 去和 14/22 对比头部开销时会对 V2 的摊销收益得出偏差。

## 五个建议
1. 【8.3.3|案例示例】行格式一节建议补一个可复算的字节级算例：16KB 页下一行含 VARCHAR(4000) + VARCHAR(4000) + VARCHAR(3000)，Dynamic 格式按"最长列先外移"走一遍，行内最后剩什么（两个 20 字节指针 + 3000 字节列 + 记录头）、为什么恰好落在 8KB 线下。现在"整行判定、最长列起移出"只有定性描述，读者拿自己的宽表算不出会不会溢出、溢出几个列。
2. 【8.4.3|深度广度】补两句压缩的真实旋钮：压缩比主要由生产者端攒批参数（`linger.ms` / `batch.size`）决定，批不饱满时 zstd 也压不出 2–6 倍；算法上 lz4 与 zstd 是"延迟-比率"取舍，可一句话点破。顺带补一句旧客户端消费新格式会触发 Broker 端 down-conversion 的解压重转代价——混合版本集群的真坑，也正好回答压缩发生在哪端的问题。
3. 【8.5.1|深度广度】表 8-2 建议加一行"压缩/编码层次"：Redis 是文件级 LZF，Kafka 是批级 zstd（生产者端），而 8.3 一节对 InnoDB 自己的页压缩（COMPRESSED 行格式、透明页压缩）只字未提。三家都做了压缩但层次完全不同，这一行对比本身就是"存储单元对齐访问单元"（启示一）的最好例证，现在这块拼图是缺的。
4. 【8.3.3|图示】图 8-4 里 Page Directory 画了 4 个空槽、User Records 画了 5 条 rec，但槽到"组末记录"的指向线没画，rec 之间也没有 next_record 链——8.3.3 文字的核心机制（每 4–8 条一组、组末入槽、二分后沿链扫）在图上全部不可见。建议把这两组关系连线画出；页头页尾 LSN 配对那条红色虚线就是现成的好范式。
5. 【8.1.2|术语使用】建议仿照"为什么没讲 LSM"的方框位置，加一个"编码术语对照"小框：RDB 的长度分档编码 = varint，Kafka V2 的相对偏移量/时间戳差值 = delta encoding，8.1.2 点名的"字典编码" = dictionary encoding，把书里的机制和通用编码术语接通。"字典编码"目前全书只在此处出现一次就没有下文，接通术语后，想读 Parquet/ORC 的读者能直接迁移，这一章的价值会外溢到列存世界。
