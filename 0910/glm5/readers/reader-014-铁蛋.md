# 读者014 · 铁蛋
身份：嵌入式 C 工程师，11年，爱好：木工
主读：第 2 章

## 五个问题
1. 【2.2.1|技术事实】书里说"短字符串用小头省内存。其中 sdshdr5 最省，整个头只有 1 字节"，但没提源码里为追加而创建的字符串会主动跳过 sdshdr5 直接给 sdshdr8（sdsnewlen 的 trymalloc 分支）——sdshdr5 连 alloc 字段都没有，天然没法预分配，运行期会增长的字符串几乎见不到这个 1 字节头。我抠了 11 年字节，拿书对源码时发现 sdshdr5 的实际出场率远比"短字符串用小头"给人的印象低，这里容易让读者产生错觉。

2. 【2.2.3|版本时效】2.2.3 结尾说"`magic` 字段标明格式版本，新旧格式可以共存"，2.3.3 又说"3.0 的 Broker 可以和 0.11 的客户端对话"——前者在 Kafka 4.0（2025 年发布，KIP-896）之后已经不成立：v0/v1 旧消息格式被直接移除，旧格式新格式的"共存"是有明确保质期的。书 2026 年出版还只拿 3.0 当最新时间点、不给共存句加版本边界，上生产的人会被这句坑。

3. 【2.3.3|技术事实】"零拷贝让一批消息不进用户态，直接从页缓存送到网卡"这个绝对表述漏了硬件前提：sendfile 只有在网卡支持 scatter-gather（SG-DMA）时才真正免掉页缓存到 socket 缓冲那次 CPU 拷贝，否则内核还是得老老实实把数据搬进 socket 缓冲再交给 DMA。我手写过 DMA 描述符链，"直接送到网卡"这五个字在老网卡上就是多一次拷贝，建议把条件写出来。

4. 【2.2.2|读不懂】行格式那段说"长度信息按与字段相反的顺序存放，解析时从记录头附近读取这些长度，再确定各字段的边界"——只说了"是什么"，没说逆序换来了什么。我照自己的习惯想在纸上画出这行内存布局，画不出逆序存放的动机；全书处处讲"为什么这么设计"，偏偏这个最反直觉的排布只给了现象。

5. 【2.2.1|逻辑论证】跳表段先说"上面几层是抽稀的索引层，每隔几个节点保留一个指针"，两段之后又说"层数逐层独立抛硬币"——前者是等距抽稀（确定性），后者是随机层数（Redis 实际是 p=0.25 的幂次定律），两种机制互相矛盾。我实现过链表结构，先读到的那句会让我把索引层画成均匀网格，后面才发现画错了。

## 五个建议
1. 【2.2.2|深度广度】"一个 16KB 页就能容纳几百个键，两层内部节点、每叶几十行，千万行的表整棵树也只有三层"这句建议给一行可复算的算术：内部节点每项 ≈ 主键(8B) + 页指针(6B) = 14B，16KB / 14B ≈ 1100+ 扇出，1100 × 1100 × 每叶行数就到千万级。嵌入式读者就是靠字节算术建立信任的，"几百个键、几十行"的模糊量级不如一个能自己验算的推导。

2. 【2.2.1|深度广度】SDS 的预分配、惰性释放和 dict 渐进式 rehash 双表，全书只讲了收益没讲内存代价：惰性释放留的洞、rehash 期间两张表并存、翻倍扩容的瞬时峰值，正是运维天天盯的 mem_fragmentation_ratio 的直接来源。这章的立意就是"选了什么就要承担什么代价"，这组设计恰好在代价侧缺席，建议补一小节串起来。

3. 【图 2-2|图示】正文把 span 讲成排行榜查名次的主角（"span 逐层累加就是名次……ZREVRANK 靠的就是它"），图 2-2 却只画了多层指针和红色查找路径，一条 span 值都没有。建议在每条前进指针上标出 span，让读者沿查找路径手动把 17 的名次加出来——图才能真正支撑导读里那个排行榜案例，否则 span 在书里始终是句空话。

4. 【2.3.2|案例示例】协议三家的例子密度不均：RESP 给了 `*3\r\n$3\r\nSET\r\n...` 完整可数字节串，Kafka 有字段表加图 2-7，MySQL 却只有 int<1>/LengthEncodedInteger 的抽象规则，没有一行真实报文。建议补一小段握手包或 OK 包的 hexdump 逐字节标注——二进制协议只有见到真字节才学得会，何况 0xFB 标 NULL 这类细节没字节流根本没法体会。

5. 【图 2-1|图示】SDS 内存图的 header 三格（len=5 / alloc=5 / flags）没标字节宽度（sdshdr8 是 1B/1B/1B），也没画 sdshdr5/8/16/32/64 分档；且 alloc 与 len 相等，图上看不出"alloc − len = 可追加空间"，"预分配 / 惰性释放"的注释在图里没有落点。看内存布局图的读者第一件事就是数字节，建议标宽度、换一个 alloc>len 的例子，让那块富余空间在图上可见。
