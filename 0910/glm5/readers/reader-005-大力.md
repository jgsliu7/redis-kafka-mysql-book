## 五个问题

1. 【1.4.3|版本时效】"版本状态提示（2026 年 9 月）"里说"Redis Open Source 的 7.2、7.4 分支仍列在官方支持范围内"，这至少对 7.2 站不住：redis.io 官方产品生命周期页（redis.io/docs/latest/operate/rs/installing-upgrading/product-lifecycle/）和 7.2.4 release notes 写明 7.2 已于 2026-02-28 结束支持、7.4 也只到 2026-11-30，OSS 线的支持周期只会更短。写"仍受支持"可能让读者放心地继续把 7.2 压在生产上，建议核对修正。

2. 【1.2.1|逻辑论证】1.2.1 说 Redis 相对 Memcached 的价值在于复杂操作不用"客户端读出来、改完再写回去"——结构化命令在服务端原子完成；可 1.1.3 又把"复杂聚合要靠客户端多次网络往返拼出来"列为 Redis 的代价。这两句在我这种只会 SET/GET 的读者眼里是打架的：到底哪些操作能一次在服务端做完、哪些必须拉回应用层拼？（顺带一问：Lua 脚本 / Function 算不算出路，书里没提。）

3. 【1.2.4 表 1-1|术语使用】MySQL 舍弃了什么，三处口径对不上：表 1-1 写"写性能"，图 1-1 写"舍弃：写入性能"，正文 1.1.3 写的是"写放大、事务开销和调优门槛"。我日常跑 MySQL 批量 INSERT 并不慢、真正肉疼的是单事务延迟和锁等待，"写性能"三个字我对应不到自己的真实痛点，雷达图 1-2 上也没有"写"这个轴——到底该记住哪个口径？

4. 【1.2.2|读不懂】"开启 binlog 时，redo log 与 binlog 还要通过内部两阶段提交协调……让崩溃恢复时能够判断事务的提交状态"——为什么两份日志必须协调、各自为政时崩溃到底出什么事故（主从不一致？还是把没提交的交易恢复了？），这里没给一个具体场景。我每天开 binlog 做主从，读到这里只能记住名词，接不上自己的经验。

5. 【1.1.1|逻辑论证】把"分布式锁"列进第一类"快速读写"、并说这类"对持久化的要求往往是尽力而为或可以重建"，我不认同：我用 PHP 写过 SETNX 抢购锁，锁数据在故障转移时丢一次就是两个进程同时进临界区、直接超卖——锁要的是互斥正确性，不是尽力而为。建议要么把锁从这个例子清单里摘出去，要么补一句"锁对正确性的要求另算"。

## 五个建议

1. 【1.2.2|结构导航】三段软件概览的海拔不齐：1.2.1 Redis 一两站地铁轻松读完，1.2.2 MySQL 却塞进 Read View 生成时机、隔离级别差异、两阶段提交这些机制细节，信息量是前者的三倍。建议 1.2 节统一保持在"出身/抽象/取舍"的高度，Read View 时机这类细节留给对应主题章展开，别让读者在第 1 章就卡壳弃书。

2. 【1.2.2|术语使用】"在每次提交都刷盘的配置下，事务提交需要等待日志落盘，可通过 fsync 等机制把缓冲的写强制刷到磁盘"——这说的其实就是 innodb_flush_log_at_trx_commit=1。表 1-2 都肯点名 sync_binlog 和 min.insync.replicas 了，正文却含糊其辞；像我这种翻 my.cnf 长大的人是靠参数名建立连接的，请直接写出参数名和档位含义。

3. 【1.2.3|表达可读】Kafka 概览里"可靠性依靠副本（replica）与 ISR……写入确认还要结合 acks 与最低 ISR 数配置……以……等条件为前提"三个从句套一句，通勤晃动中我跟丢了两回。建议拆成"什么组合保证不丢（acks=all + min.insync.replicas）/哪几种情况仍会丢"两三个短句，并在此处就点出参数名——别让表 1-2 反而比正文先用上这些名词。

4. 【1.3.3|案例示例】三层追问（先刷日志还是先刷页、落盘粒度多细、记逻辑还是物理）是全章最让我兴奋的部分，但只停在"问"上。建议配一张三行小表把追问落到三家的真实参数上——AOF appendfsync=everysec 最多丢 1 秒、innodb_flush_log_at_trx_commit=1 每提交必刷、acks=all + min.insync.replicas——给背参数出身的人一条从使用视角爬到架构视角的梯子。

5. 【1.4.1|结构导航】前置要求的两档标准不一致：数据结构只要"名词不陌生"，操作系统却要"I/O 多路复用能大致说清"——培训班出身的我前者达标、后者真不行（PHP 没暴露过 epoll，Go 又把它藏进 net 包了）。建议给三五道自检题（例如"说清 epoll 与多线程阻塞 I/O 的差别"）让读者开读前自己校准，而不是读到第 2 章才发现地基缺一块。
