# 读者121 · 网关酱
身份：Envoy/网关研发，6年，爱好：悠悠球
主读：第 5 章

## 五个问题
1. 【5.4.1|技术事实】"受 Netty 的 Reactor 模式启发，但用 Scala 实现"这句我专门去核了源码：SocketServer.scala 在 trunk、0.10.2.2、2.8.2 三个版本全文都没出现 Netty 或 Reactor，类注释只写 "1 Acceptor / N Processor / M Handler"，社区文章反而拿"Kafka 不用 Netty、自己拿 Java NIO 手写"与 RocketMQ 对比。"受 Netty 启发"的出处是哪里？查不到的话建议改成"实现了经典的主从 Reactor 模式（Reactor 模式出自 POSA2）"。
2. 【5.4.1|深度广度】正文把"队列满 → Processor 入队阻塞 → 阻塞网络 I/O"完全当褒义的"天然背压"，但这根有界队列是所有 Processor 共享的一根 ArrayBlockingQueue（默认 queued.max.requests=500），满载时整个 broker 的网络读一起停——一个疯狂客户端能拖住全部连接，这种全局牵连在网关侧是要用 per-connection 水位线去避免的。5.4.2 的配额（quota）才是按客户端的细粒度限速，可两节各说各的，读者拼不出 Kafka 真正的过载保护组合拳（粗队列刹车 + 细 quota 限速）。
3. 【5.2.2|图示】图 5-1 的纵向箭头只能读作时间顺序，可"⑥ robj 存取"排在"④ 命令执行"和"⑤ 慢查询/MONITOR 钩子"之后——robj 存取实际就发生在 cmd->proc 内部（④），⑤里列的"复制传播"之后跟的才是 AOF/RDB。⑥把"执行中发生"和"执行后发生"两件事装进同一个后置步骤，时序画歪了。
4. 【5.2.4|术语使用】开头说 Redis"全程无序列化、无虚函数"，四句之后又承认"命令分派用的是函数指针（cmd->proc）"——函数指针就是间接调用，和 5.3.3 批判的 handler 虚函数在机制上是同一件事，真正的差别是频次（每命令一次 vs 每行一次）。"无虚函数"这个绝对化说法和 5.3.3 对照读像双标，建议改成"每命令只付一次间接跳转"。
5. 【5.5|逻辑论证】表 5-1"可插拔性"一行，Redis 格是光秃秃的"未提供可插拔引擎接口"，Kafka 格却补了"另有 Connect/Streams 插件生态"；可正文 5.2.2 和启示二都明确承认 Redis 有 Modules（运行时注册新命令）生态。同一维度两家口径不对称，Modules 到底算不算 Redis 的可插拔点？建议 Redis 格同样加注"逻辑层有 Modules API"。

## 五个建议
1. 【5.6 启示四|案例示例】"空洞透传"拿"只转发的 API 网关"当反例，干网关六年我得替它说句话：纯转发层也干着连接复用、缓冲、TLS 终止、keepalive 池这些实事，nginx 的四层 stream 代理就是"只转发"却谁也离不开。反模式的要害是"零职责"而非"没做业务逻辑"，建议换成"Service 层把参数原样转交 Manager 层"这类真零职责的例子，免得中间件读者觉得被误伤。
2. 【5.4.1|图示】图 5-5 里"响应入队"的红虚线直接指回 RequestChannel 那个装满 req 的"有界队列"大框，读者会误以为响应也挤同一根有界队列、受同一背压；实际响应走的是每个 Processor 独立的 responseQueue。建议把回程画成独立通道，或在框上注明"响应队列独立"。
3. 【5.4.3|深度广度】零拷贝的 TLS 例外只有一句"不能直接这样转发"，没给量级。我们生产网关上 TLS 转发比明文 sendfile 吞吐要掉三四成，broker 上的 FETCH 开 TLS 后同样要把数据拉回用户态加解密。建议补一个公开压测数字或代价量级，让"硬前提"三个字有痛感，也帮读者做"broker 要不要上 TLS"的决策。
4. 【5.4.4|结构导航】协调层被立为本章 Kafka 侧四段之一、单独占了小节号，正文却只有半页且大半在说"细节留给第 7 章"，按小节标题来的读者期待会落空。建议要么补一段最小可独立阅读的机制描述（哪怕一句 ISR 收窄的机制加"为什么它塞不进前三层"），要么把它并进 5.4 开头的框架段、不单占小节号。
5. 【5.5|深度广度】三段式（交互/逻辑/存储）其实和读者天天摸的代理栈完全同构——Envoy/nginx 的 listener → filter chain → router → connection pool 就是同一副骨架，但全书唯一一次提 API 网关还是拿它当反模式。建议在 5.5 或 5.6 加一小段把三段式映射到这类日常中间件，帮网关/后端读者把三个软件的分层经验搬运进自己的系统。
