# 读者116 · Oracle老
身份：Oracle 老 DBA，20年，爱好：茶宠收藏
主读：第 4 章

## 五个问题

1. 【4.3|深度广度】"InnoDB 没有直接用朴素 LRU，而是把它改良成了'新老分区'"——读到这里我停了很久。这套 midpoint 插入 + 冷热分区 + 停留时间门槛（`innodb_old_blocks_time`）的结构，和 Oracle buffer cache 从 8i 起就用的中点插入（midpoint insertion）+ touch 计数是同一套东西，防的也是同一个"一次性扫描污染热区"。书里写成 InnoDB 自己的改良，不点谱系出处，老兵读着像看人把前辈的轮子重新发明一遍还以为是原创。

2. 【4.5|技术事实】表 4-3 崩溃恢复代价 MySQL 一栏只写"重放 redo log + 恢复脏页"，漏了恢复的第二阶段：undo 回滚未提交事务。Oracle 的 crash recovery 前滚 + 回滚两阶段是我们吃饭的常识，InnoDB 大事务崩溃后的后台回滚同样可能拖几个小时；且"恢复脏页"这个说法也别扭——崩溃后内存脏页已经没了，redo 重做的是磁盘页。另外正文说"重放 redo log 较快"，而第 8 章 8.7 说"崩溃恢复还要按 checkpoint 之后的日志量重放 redo"，后者才是严谨口径，脏页积压/checkpoint 滞后时前者不成立。

3. 【4.4|结构导航】`acks`（0/1/all 三档）在 4.4 首次出场只报名字不给语义，一句"完整语义见第 7 章、精确交互见第 9 章"把读者推走；等读到 4.6 启示三才补上 all 是"等待 ISR 全体确认"，而 0 和 1 两档的语义在第 4 章始终没有着落。这一章的主线就是持久化谱系对照（和 `appendfsync`、`innodb_flush_log_at_trx_commit` 同台），手里没有三档语义，启示三的对照表我根本消化不了。

4. 【4.1|逻辑论证】表 4-1 拿"单线程内存随机读（几百 MB/s）"当顺序吞吐的参照，我第一反应是这数字哪来的——想明白才发现是逐次访问的延迟倒数（100ns 一次，每秒千万次乘 64B 约六百 MB/s）；同一格里给 NVMe 定位又换成"内存带宽"口径（DDR4 双通道几十 GB/s），两个参照物差着两个数量级。做容量规划汇报时若引用这张表得出"顺序写盘已接近内存"的结论，会被懂行的人当场抓住。

5. 【4.2|逻辑论证】"`noeviction` 是内存满了直接报错、不淘汰，适合'数据不能丢'的场景"——"不淘汰"和"不丢"是两个轴上的事：noeviction 只承诺不静默驱逐键，持久化该丢还是丢（AOF 关着就全丢，everysec 也有 1 秒窗口）。4.1 刚刚把"数据放哪里"和"持久化怎么做"郑重立成两条轴，这句表述自己又把两条轴搅在一起了；它真正适合的是"把 Redis 当可写主存储、宁可写失败也不静默丢键"的场景。

## 五个建议

1. 【4.3|案例示例】"核心假设"里"大报表跑完整体延迟上升"的故事只有定性没有数字。建议配一个量级示意框：64GB 缓冲池、1TB 库、日常命中率 99% 上下，一次两百 GB 的扫描过后命中率掉到九成以下、未命中量放大十倍、P99 从毫秒级抬到几十毫秒，再随热页回温回落。我们讲缓冲池污染都是拿命中率前后对照讲的，有数字 DBA 才真的信。

2. 【4.3|技术事实】LRU 新老分区一节补半句谱系："这与 Oracle 缓冲池的中点插入 + touch 计数同构"，`innodb_old_blocks_time` 对应 Oracle 的 touch 时间阈值。点出先例不但不减 InnoDB 的分，反而正强化本书"同一问题长出同一机制"的主线——这正是本书最值钱的观察方式。

3. 【4.3|深度广度】双写缓冲对付的 torn page（部分写失效）是数据库界的经典战场，同一问题 PostgreSQL 给了另一个解法：full_page_writes，checkpoint 后首次改一页时把整页映像写进 WAL，用日志带宽换；Oracle 则传统上把赌注押在 OS/存储的原子写语义上。建议加一个小对照框——"同一故障、三种解法"是本书横切方法论在节内的小规模示范，比单讲 InnoDB 一家更见功力。

4. 【4.5|术语使用】"物理到页、逻辑到操作的混合日志"这个概念在第 4 章 4.5 和第 8 章 8.3.4 各描述了一遍，但都没给标准术语 physiological logging（Gray & Reuter《Transaction Processing》的叫法；Oracle 的 change vector 是同族）。既然全书 redo log/WAL 都按英文术语规范写，这里也该给个英文术语锚点，读者才能顺藤摸到文献。

5. 【4.4|图示】图 4-6 的图注扛了约 250 字的正文：4 次拷贝、4 次/2 次上下文切换、scatter-gather DMA、PageCache 前提全塞在图注里，而正文只有一句"下图把零拷贝数据流画出来"。建议机制细节移进正文、图注只留一句结论（"传统 4 次拷贝 4 次切换，sendfile 路径数据不进用户空间"），现在这样读图注比读正文还累。
