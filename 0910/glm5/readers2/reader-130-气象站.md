# 读者130 · 气象站
身份：业余气象观测程序员，10年，爱好：观云
主读：第 6 章

## 五个问题
1. 【6.3|逻辑论证】6.2 给 alice 的规则是 `ACL SETUSER alice on >pwd ~keys:* +get +set`（按命令名授权），但 6.3 图 6-3 的解释说授权检查「分别检查命令类别（GET 属于 @read）和键模式两个维度，两项都命中才放行」——alice 的规则里根本没有 `+@read`，照这个二维检查逻辑 GET 应该被拒才对。实际 Redis 里 `+get` 精确匹配也能放行，但书把「命令维度」统一说成「命令类别」，示例和解释对不上，我在这停了五分钟。
2. 【6.2|读不懂】「SCRAM 可以用于 Broker 间通信，Kafka 3.5.0 也加入了 Broker 到 Controller 的 SCRAM 支持；这与 Controller 之间的共识连接不是同一条路径。后者在 3.5.1、3.6.0 曾出现用 SCRAM 启动集群失败的问题」——这段读了两遍没读懂：启动期凭证为什么是鸡生蛋问题（SCRAM 凭证存在元数据日志里、而元数据要集群先起来）书里只在结尾暗示了半句，3.5.1/3.6.0 的版本 bug 更像 changelog 摘抄，不知道和我这样的读者有什么关系。
3. 【6.4|技术事实】说社区版可用 `keyring_file` / `component_keyring_file` 做 TDE，但没提这两个组件官方定位是「仅供开发测试、不建议生产」；更要命的是密钥文件就存在同一块盘上——6.1 刚说过存储加密要保证「磁盘被盗也无法直接读取」，用 keyring_file 时密钥跟着数据一起被偷走，这个承诺根本不成立。我在树莓派上琢磨 SD 卡被拔的场景，这个缺口一眼就看到了。
4. 【6.5|逻辑论证】「务实的选择是异步写入审计日志、对日志采样，或外接专用审计系统」——采样意味着审计轨迹天生有洞，取证时「谁在什么时候做了什么」恰好落在没采到的那批里怎么办？对一个观测数据缺一条都难受的读者，这句轻描淡写地牺牲了审计的定义性属性，至少该说清采样只适用于性能类审计、不能用于合规取证。
5. 【6.3|技术事实】「Redis 把上百条命令归成二十来个类别」——我在自己树莓派的 Redis 7 上跑 `ACL CAT` 数下来是三十多个类别（含 @bitmap、@module、@stream 这些），「二十来个」口径存疑，建议核对一下版本。

## 五个建议
1. 【6.4|深度广度】TLS 性能讨论全程默认 x86 服务器：「用硬件指令（AES-NI）」「专用硬件做加密卸载」——我在树莓派 4（Cortex-A72，没有 AES 硬件指令）上给传感器数据上传开 TLS，CPU 占用是实打实吃掉的。建议补一两句「低算力设备/无硬件加速时的 TLS 代价」，边缘场景的读者会立刻对号入座。
2. 【6.2|案例示例】委托令牌那段正对物联网/传感器场景——几十上百个采集或工作进程不想各自分发 SCRAM 密码，这恰恰是它的价值，但书里只有抽象描述。建议补一个具体小案例（比如作业分发系统怎么申请、续期令牌），这个痛点不点透可惜了。
3. 【6.4|案例示例】表 6-1 里 Redis 存储加密「无原生」一句话带过。像我这种把 Redis 塞进树莓派、SD 卡随时可能被拔的人，想知道的是实操替代：文件系统级加密（LUKS）或卷加密的取舍在哪。给一行落地指引，「无原生」才从判词变成答案。
4. 【6.3|图示】Redis 有时序图（图 6-3）、MySQL 有层级图（图 6-4），偏偏最抽象的 Kafka ACL——三元组怎么绑定、前缀授权怎么匹配、默认拒绝怎么兜底——一张图都没有。建议补一张「一条请求带 Principal/Operation/Resource 走 ACL 匹配」的示意图。
5. 【6.3|表达可读】protected-mode 那段「是否绑定全部网卡不是这一判断的条件」是在反驳一个文中从没出现过的误解，读起来像修订时打的补丁。建议先正面讲清判定条件（保护模式开 + default 带 nopass → 拒非本地连接），删掉这句对不存在误读的反驳。
