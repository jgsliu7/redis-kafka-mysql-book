# V027 · ch3 · 命令实操视角

审读对象:chapters/03-lifecycle/chapter.md(基线 Redis 7.x / MySQL 8.0.x / Kafka 3.x)。身份:8 年 DBA/运维。仅挑命令/配置/参数/实操相关且经核实的表述。已核实为正确、不挑的项:Redis `shutdown-timeout` 默认 10 秒(L55/L206)、tcp-backlog 默认 511(L40)、Kafka `controlled.shutdown.enable` 默认 true 且 read-only(L173)、`num.network.threads=3`/`num.io.threads=8`(L158)、`controlled.shutdown.max.retries=3`/`retry.backoff.ms=5000`(L189)、`terminationGracePeriodSeconds` 默认 30 秒(L181)、`innodb_fast_shutdown` 默认 1 及三档行为(L107-121)。

| 1 | L66 | **第五步释放资源并 exit**,交还文件锁、内存、进程身份。 | Redis 关闭流程里没有"文件锁"可交还:Redis 不对数据文件/pidfile 加任何文件锁。`prepareForShutdown` 实际做的是删除 pidfile、unlink unix socket 文件、关闭监听 socket 后 exit。"文件锁"是另外两家的真实概念——Kafka 关闭时释放 log.dirs 下的 `.lock`,InnoDB 持有 ibdata 的文件锁——放在 Redis 一节属于张冠李戴。建议改为:"第五步释放资源并 exit,关闭打开的文件、删除 pidfile 和 unix socket 文件、回收内存。" | 事实 |
| 2 | L70 | `systemctl stop redis` 背后其实就是发一个 SIGTERM。 | 不止"一个":systemd 默认 KillMode=control-group,`stop` 是向 cgroup 内**所有**进程发 SIGTERM——包括正在跑的 BGSAVE/BGREWRITEAOF 子进程(官方 redis.service 未显式设 KillMode,走默认)。而且 systemd 还有第二段:`TimeoutStopSec`(默认 90 秒)超时后对残存进程发 SIGKILL,这一段恰与本章 3.4 节 K8s 的 `terminationGracePeriodSeconds` 论述同构,补上反而前后呼应。建议改为:"`systemctl stop redis` 背后是给 cgroup 里每个进程(含正在跑的 BGSAVE 子进程)发一个 SIGTERM,超过 `TimeoutStopSec`(默认 90 秒)还没退干净就补 SIGKILL。" | 事实 |
| 3 | L72 | Kafka 稍有不同,它的进程跑在 JVM 里,SIGTERM 先由 JVM 的 Shutdown Hook 捕获,再交给应用代码走清理流程。 | 机制倒置:Shutdown Hook 不是信号捕获器,也不能"捕获"SIGTERM。实际路径是:SIGTERM 由 JVM 内建的信号处理器(os signal handler)接收 → JVM 启动关闭序列 → **并行**启动所有通过 `Runtime.addShutdownHook` 注册的 hook 线程(Kafka 在自己的 hook 里调 `kafkaServer.shutdown()`),等全部 hook 跑完才退出。"先由 Shutdown Hook 捕获"会让读者以为 hook 是信号处理的第一站、是串行交接,两处都不对。建议改为:"SIGTERM 由 JVM 内建的信号处理器接收,JVM 随即启动关闭序列,并行执行注册的 Shutdown Hook;Kafka 在自己的 Hook 里走应用层的清理流程。" | 事实 |
| 4 | L82 | 按固定顺序读取多个 my.cnf 路径(Unix 上从 `/etc/my.cnf` 读到 `~/.my.cnf`,同名选项后读的覆盖先读的),再叠加命令行覆盖。 | "再叠加命令行覆盖"这个分层模型在 8.0 下对 persisted 参数不成立,恰是本段讲的"参数没生效"排障里最反直觉的一层:MySQL 8.0 官方文档明确 mysqld-auto.cnf 的取值**优先于命令行选项**(server 处理顺序 mysqld-auto.cnf → option files → … → command options,persisted 值获胜;Percona 亦确认"values in mysqld-auto.cnf take precedence over the command-line options")。也就是说本行末尾列举的"或启动命令行参数"并不是终极覆盖层——只要参数被 SET PERSIST 过,命令行也压不过它,必须 `RESET PERSIST` 或启动时加 `--persisted-globals-load=OFF`。建议在段末补一句:"8.0 还有个反直觉的例外:`mysqld-auto.cnf` 的持久化值优先级在命令行参数之上,命令行也覆盖不了被 SET PERSIST 的参数,得先 RESET PERSIST。" | 事实 |
| 5 | L132 | `SHOW PROCESSLIST` 在关闭期的输出,对着这四类根因看,就能定位卡点。 | 生产上不成立:mysqld 一进入关闭流程就**先关闭监听**(官方 server-shutdown 文档:TCP 端口、Unix socket、named pipe 全部关闭,拒绝新连接),存量连接随即被标记死亡;而本节列的四类根因(脏页刷、长事务回滚、复制线程、FTS)对应的工作都发生在客户端连接断光之后的存储引擎层。真到了"关不掉"挂住时,新连接报 ERROR 2003/1053,`SHOW PROCESSLIST` 根本无从执行。实操顺序是反的:要在**发起 SHUTDOWN 之前**先留存一份 `SHOW PROCESSLIST`(以及 `performance_schema` 快照);挂住之后能看的是 error log 里的 `[Shutdown]`/Waiting 类消息,配合 `pstack`/`gdb thread apply all bt` 看线程栈定位卡点。建议改为:"排障要抢在发起 SHUTDOWN 之前先抓一份 `SHOW PROCESSLIST`;关闭一旦开始,监听 socket 先被关掉,新连接进不来,这条命令就没机会执行了。真挂住时看 error log 的 [Shutdown] 消息,再用 pstack 看线程栈。" | 命令 |
| 6 | L151 | 八个阶段全部走完,Kafka 才对外打印 `[KafkaServer id=0] started` 这条就绪日志,和 Redis 的 `Ready to accept connections`、MySQL 的 `ready for connections` 是同一类信号。 | 这行就绪日志是 **ZooKeeper 模式**的(完整行为 `[KafkaServer id=0] started (kafka.server.KafkaServer)`);而本章 3.4 节明确以 KRaft 为主线(L143 大篇幅讲 KRaft、L153 称 3.3 起生产可用、4.0 移除 ZK)。KRaft 模式下 broker 的启动类是 BrokerServer,server.log 里的就绪标志是 `[BrokerServer id=0] Transition from STARTING to STARTED`(进程级另有 `[KafkaRaftServer nodeId=0] Kafka Server started`),`[KafkaServer id=0] started` 这行**不会出现**——运维脚本照书 grep 会永远等不到就绪,就绪探针直接失灵。建议注明模式差异:"KRaft 模式下这条就绪日志是 `[BrokerServer id=N] Transition from STARTING to STARTED`(ZK 模式下才是 `[KafkaServer id=N] started`),写就绪脚本时要按部署模式 grep 对应那条。" | 命令 |
| 7 | L185 | 且此时 Pod 已摘流、无新写入,写时复制(COW)几乎为零,全量落盘赶在 kill 期限之前真正落成 | "此时 Pod 已摘流"不成立:K8s 把 Pod 从 Service endpoints 摘除是**异步**的,与 preStop/SIGTERM 并行推进,官方文档明确存在"摘流量尚未完成、SIGTERM/preStop 已开跑、请求仍在进来"的窗口(这正是社区 preStop 里先 sleep 几秒的惯例由来)。BGSAVE 若在摘流生效前启动,COW 几乎为零的论证前提就悬空了。且这与 L193 实践清单"preStop hook 主动检查条件而非 sleep"可以呼应:要检查的第一个条件就是流量已停。建议改为:"摘流是异步的,prePost 开始时未必已生效,先确认流量停了再触发 BGSAVE,写时复制(COW)才能压到接近零……" | 事实 |

## 核实来源

- mysqld-auto.cnf 优先级:MySQL 8.0 官方文档(set-variable / server-system-variable-reference,server 处理选项顺序 mysqld-auto.cnf → option files → command options)、Percona "mysqld-auto.cnf: A serious failure factor in MySQL 8.0"
- MySQL 关闭期拒连:MySQL 8.x 官方文档 The Server Shutdown Process(关闭伊始即关闭 TCP/Unix socket/named pipe 监听);ServerFault 多起 "Server shutdown in progress" 挂住案例(连接被拒,靠 error log + pstack)
- KRaft 就绪日志:Kafka 官方 KRaft operations 文档及 Strimzi GitHub 讨论(BrokerServer/`Transition from STARTING to STARTED`);`[KafkaServer id=N] started (kafka.server.KafkaServer)` 为 ZK 模式 KafkaServer 类日志
- controlled.shutdown.enable 默认 true / read-only:Apache Kafka 官方 Broker Configs(v3.7/v4.1)
- Redis shutdown-timeout 默认 10 秒:Redis 官方 SHUTDOWN 命令文档
- systemd SIGTERM 行为(KillMode=control-group 默认、TimeoutStopSec):systemd 官方手册常识,未单列来源
