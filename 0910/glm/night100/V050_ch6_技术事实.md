| 3 | L58 | 新插件用 SHA-256 哈希，首次连接走完整的挑战—响应握手，之后服务端把哈希结果缓存在内存里，后续连接走快路径。 | 两条路径的机制张冠李戴。caching_sha2_password 的"完整认证"（首次/缓存未命中，例如重启或改密码后）并不是挑战—响应，而是客户端把密码本身用服务端 RSA 公钥加密后传过去（或在 TLS 通道内传输）——这正是官方文档说的 full authentication 需要 secure connection 的原因；真正基于随机数扰乱的挑战—响应（客户端 XOR scramble）发生在缓存命中的"快路径"上。建议改为：首次（缓存未命中）要求安全通道，客户端用服务端 RSA 公钥加密密码（或走 TLS）完成完整认证；之后服务端缓存哈希，后续连接走基于随机数扰乱的挑战—响应快路径。 | 事实 |
| 4 | L117 | 注意：FILE 权限能读写服务器文件系统，配合 SQL 注入可读任意文件，是高敏权限的典型。 | 在 8.0 基线下"可读任意文件"言过其实。MySQL 8.0（含 5.7 起）`secure_file_priv` 默认为平台相关的非空目录（Linux 上为 `/var/lib/mysql-files/`），LOAD_FILE / LOAD DATA / INTO OUTFILE 只能读写该目录内的文件，默认配置下 FILE 权限读不了 `/etc/passwd` 这类任意路径（要读任意文件需管理员把 secure_file_priv 设为空串或目标文件恰在许可目录内）。FILE 当然仍是高敏权限（目录内任意读写 + 一旦 secure_file_priv 被放宽即可读任意文件），建议补一句默认限制，例如：配合 SQL 注入可读写 `secure_file_priv` 许可目录内的文件（8.0 默认非空，放宽为空串后才能读任意路径）。 | 事实 |
