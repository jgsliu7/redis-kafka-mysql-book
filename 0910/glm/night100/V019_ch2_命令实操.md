审读人设：8 年 DBA/运维工程师，redis-cli / mysql / kafka 命令行参数与默认值烂熟。只审 chapters/02-data-structures-protocols/chapter.md 中与命令/配置/参数/协议细节相关的表述。基线版本：Redis 7.x / MySQL 8.0.x / Kafka 3.x。

说明：本章命令与协议细节总体准确度很高（RESP 示例字节、33 字节计数、LengthEncodedInteger 分档、api_key 编号、61 字节 Batch 头、set-max-intset-entries=512、AHI 5.7.8 起 8 分区、batch.size/linger.ms、0xFF/0xFE/253 等均已逐一验证无误）。以下 5 条是验证后确认有出入的表述。另有一处疑似（表 2-1 `baseTimestamp` 与 KIP-98 原文的 `firstTimestamp` 命名不一致）经查 Kafka 官方文档 3.x 各版本页面均写 `baseTimestamp`，与书一致，**不构成错误，未列入**。

## 核实依据

- 条 1/2（ZRANGE 复杂度）：redis.io/commands/zrange — "O(log(N)+M) with N being the number of elements in the sorted set and M the number of elements returned"。
- 条 3（定时 rehash 范围）：redis/src/server.c — 7.4 及以前 incrementallyRehash 仅执行 dictRehashMilliseconds(db->dict, 1) 与 dictRehashMilliseconds(db->expires, 1)；db->dict/db->expires 为键空间与过期字典，不含用户 hash/ZSET 内部 dict。serverCron 经 run_with_period(100) 每 100ms 触发，hasActiveChildProcess() 时跳过（与 L52 后半句一致）。
- 条 4（intset 升级）：redis/src/intset.c — intsetAdd 检查 _intsetValueEncoding(value)，超档即调 intsetUpgradeAndAdd；后者按新值定档，一趟 back-to-front 重编码全部旧元素，无 int32 中间态。
- 条 5（RESP3 前缀）：redis.io RESP3 规范（redis.io/learn/whatredis/redisprotocol）新增类型标记 `,` Number、`(` Big number、`#` Boolean、`!` Bulk error、`=` Verbatim、`%` Map、`~` Set、`_` Null、`>` Push。
- 未列入项（baseTimestamp）：Kafka 官方文档 kafka.apache.org/33/implementation/message-format（3.x 各版本页面一致）中 RecordBatch 字段为 baseTimestamp: int64 / maxTimestamp: int64，与书一致；KIP-98 原文与 Java 客户端（DefaultRecordBatch.firstTimestamp()）用 firstTimestamp，属命名来源分歧，书不算错。
