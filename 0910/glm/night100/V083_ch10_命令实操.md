| 1 | L123 | 开 `enable.idempotence=true`（它内部会强制 `acks=all` + 重试，挡住"重复写入"和"生产者重试导致的乱序"） | 基线 Kafka 3.x 下这条建议已过时：KIP-679 自 3.0 起生产者默认 enable.idempotence=true、acks=all、retries=Integer.MAX_VALUE，读者去"开"会发现本来就开着，反而困惑。宜标注版本："3.0 起生产者默认已开启幂等（acks 随之默认 all），2.x 才需显式设置"。另注：所谓"强制 acks=all"的实际表现是——用户显式设 acks≠all 时 3.0–3.5 直接抛 ConfigException，3.6 起（KAFKA-13673）改为自动禁用幂等并打 warning，两种行为都值得一句话说破。 | 事实 |
| 2 | L145 | acks=all 接近 0 | 表 10-2 RPO 行 Kafka 列。acks=all 只等 ISR 内副本确认，而 min.insync.replicas 默认为 1：当 ISR 收缩到只剩 leader 时，acks=all 退化为 leader 自确认，此时 leader 宕机已确认消息照样丢，RPO 远不"接近 0"。"接近 0"的成立前提是 replication.factor≥3 + min.insync.replicas≥2。正文 L72 已写"配合 min.insync.replicas"，表格把前提丢了，且同行 Redis 列都注明了"（开启 AOF 后）"，唯独 Kafka 列裸写。改进："acks=all + min.insync.replicas≥2 接近 0"。 | 命令 |

| 4 | L148 | MGR 在线加成员（全员全量、无数据再均衡，读流量可经 Router 分摊） | "全员全量"字面会被读成"加一个成员、全组成员都做一次全量"，吓退运维。实际行为：只有新成员做一次全量恢复（MySQL 8.0.17+ 可由 clone 插件自动完成，更早版本需手动备份恢复），存量成员不动。作者本意应是"MGR 每个成员持全量数据、因此无数据再均衡"。改进："新成员需一次全量恢复（8.0.17+ 可由 clone 插件自动做），存量成员不动，组内无数据再均衡"。 | 可懂性 |
| 5 | L150 | slowlog + latency monitor | 表 10-2 故障排查行 Redis 列。latency monitor 默认是禁用的：latency-monitor-threshold 默认 0，不采集任何事件，读者出问题时直接敲 LATENCY DOCTOR / LATENCY HISTORY 只会得到空结果。slowlog 默认就工作（slowlog-log-slower-than 默认 10000 微秒），两者不对等。改进："slowlog + latency monitor（后者需先 CONFIG SET latency-monitor-threshold 100，默认 0 不采集）"。 | 命令 |
| 6 | L171 | 最后把 Kafka 的 `acks` 从 all 改成 1，断一个 Broker 看消息丢不丢。 | 基线 Kafka 3.x 下这个实验照书做不出来：生产者默认 enable.idempotence=true，要求 acks=all。只改 acks=1：3.0–3.5 客户端 producer 直接抛 ConfigException 起不来；3.6.0 起（KAFKA-13673）改为自动禁用幂等打 warning——实验能跑，但实际测的是"acks=1 + 幂等被悄悄关掉"的组合。改进：注明"需同时显式设 enable.idempotence=false，否则与 3.x 默认幂等冲突（早期版本直接起不来，3.6 起被自动禁用）"。 | 命令 |

## 类型分布

命令 4、事实 2、可懂性 1。

## 核实依据（WebSearch）

- Cluster Linking 为 Confluent 专有、Apache Kafka 无此功能：Stack Overflow 讨论（"limited only to Confluent"）与 Confluent 官方文档（docs.confluent.io/platform/current/multi-dc-deployments/cluster-linking/）；Apache Kafka 开源版跨集群复制用 MirrorMaker 2。
- Kafka 3.0 起幂等默认开启 + acks=1 冲突：KAFKA-13598（3.0 默认开幂等）、KAFKA-13673（冲突配置改为自动禁用幂等，落版 3.6.0）、Apache Kafka 官方 Producer Configs 文档。
- Redis latency monitor 默认禁用：Redis 官方文档 Latency monitoring（"CONFIG SET latency-monitor-threshold 100" 为启用步骤，默认 0 不采集）。

## 未挑但核对过的表述（均无误）

- L72/L98：appendfsync 三档与 everysec 为 AOF 开启后默认值、最坏丢约 1–2 秒；innodb_flush_log_at_trx_commit=1 与 sync_binlog=1 在 MySQL 8.0 均为默认（双 1）；双写缓冲防页撕裂的表述。
- L104：Redis 6.0 起 io-threads 可开、默认关，仅卸载网络读写。
- L123："enable.idempotence 内部强制 acks=all + 重试"机制本身（意见 1 只挑版本语境，不否认机制）。
- L171 另两处：MySQL 从 1 改 0 后强杀进程能复现丢数据（0 档下日志仍在进程内存，kill -9 即丢，最多约 1 秒——若改成 2 则 kill -9 不丢、仅断电丢，0 与 2 的这一区别书里没提但不算错）。
