## 附：已核实、未列入意见的部分（避免后续重复排查）

- **L150 预编译语句"执行计划则在每次执行时按当时的统计信息重新生成"**——已实测验证书稿是对的，不挑。本地 MySQL 8.0.27（与基线 8.0.x 一致），用 performance_schema 阶段事件观测：预编译语句第二次 EXECUTE 仍完整经过 `stage/sql/optimizing`、`statistics`、`preparing` 阶段，与普通查询的各阶段完全对应，说明社区版 MySQL 8.0 确实每次执行重新优化（这也与云厂商要在自研内核里另加 Plan Cache 特性互为佐证）。
- **L52 "做 RDB/AOF 的子进程在场时它暂停"**——与 Redis server.c `databasesCron()` 的 `hasActiveChildProcess()` 守卫（注释明言 rehash 会造成大量 copy-on-write）一致，正确。
- **L122 图注"61 字节头部"**——逐字段相加 8+4+4+1+4+2+4+8+8+8+2+4+4=61，正确。
- **L94** AHI"5.7.8 起拆成 8 个分区"、**L48** SipHash（Redis 4.0 起）、**L70** set-max-intset-entries 默认 512 / set listpack 门槛 128 及 7.2 前后行为、**L31/33/34** SDS 头部字段与翻倍/惰性释放策略、**L59/64** ziplist 连锁更新与 254/0xFE/0xFF、**L148** LengthEncodedInteger 分档（<0xFB / 0xFC/0xFD/0xFE → 总长 1/3/4/9 字节，0xFB 在结果集行中标记 NULL）、**L158** Produce=0/Fetch=1/Metadata=3——均核实无误。
