## 核查过程（逐类扫过哪些）

1. **命令与命令修饰符**：L20 SHUTDOWN 的 SAVE/NOSAVE 两条路径（语义核对无误：SAVE=关闭前强制落盘、NOSAVE=不落盘退出，默认路径随持久化配置，概括成立）；L59 PSYNC 部分重同步。均准确。
2. **配置参数与标识符格式**：L37 `requirepass`（仍为有效参数，等价于为 default 用户设密码）；L60 GTID 格式 `source_id:transaction_id`（与 MySQL 8.0 refman replication-gtids 页表述一致）；L59 replid/replid2。均准确。
3. **机制行为断言**：逐条核对 L13（RESP 与 RDB 编码思路，附注自我声明"官方未发布字节级 RDB 格式规范"，观点性概括可接受）、L15/L50（RecordBatch V2 增量 offset/timestamp 编码、幂等与事务字段，KIP-98 引入 V2 格式属实）、L21（ARIES 分析→重做→回滚三阶段）、L22（controlled shutdown 时 Leader 迁移）、L26（Free/LRU/Flush 三链、doublewrite、change buffer）、L32（Handler API vtable）、L33（Reactor 模型与有界队列）、L37（ACL 命令类别与键模式）、L38（五级权限、8.0 roles、表空间与日志加密）、L43（16384 槽、Gossip、SDOWN/ODOWN）、L44（XCom Paxos 变体、少数派退出）、L45（KRaft 百万级分区）、L51（16KB 页七段布局，与 Internals Manual 的 Fil Header/Page Header/Infimum+Supremum/User Records/Free Space/Page Directory/Fil Trailer 一致；16KB 为默认页大小且建库后不可变，"固定"表述可接受）、L52（RDB 长度编码高 2 位档位 00/01/10/11、CRC64 校验）、L57/L58（KIP-101/KIP-320 按 leader epoch 截断防 HW 误截断）。除 L14 外均与实际行为相符。
4. **外部验证两处**：(a) 全文抓取 redis.io 官方 replication 页（L59 所引 URL）核对——页面以 "main ID / secondary ID" 名义完整描述了双 replication ID、failover 后部分重同步与 replication backlog，附注用源码字段名 replid/replid2 指称同一机制，实质有据，未立项；(b) 经 Redis 7.0 release notes 及多方信源确认 listpack 自 7.0 起取代 ziplist、相关参数改名，支撑上表第 1 条。
