# 作者风格保真审读经验

本页记录作者手改序言及后续语言审读中可复用的经验，补充“怎样识别作者的实际选择，怎样迁移而不改义”。四维诊断、采信阈值、完整改稿与执行制度沿用 [语言组织审读方法](语言组织审读方法.md) 和 [AGENTS.md](../AGENTS.md)，这里不另设流程，也不把指定范围的任务扩展为全书审查。

## 1. 先分清证据来源，再归纳风格

提炼前，核对最后实际交付稿与作者手改稿的确切版本，保存完整差异。不能拿更早的 AI 草稿冒充手改前基线；当前文件又变时，应重新核对受影响证据。

每项观察至少说明四件事：作者改了什么、改动在段落中完成什么任务、适用于哪些位置、哪些内容限制了这项推断。

| 证据类型 | 可以说明什么 | 不能据此推断什么 |
|---|---|---|
| 作者新增或主动改写 | 本次确实采用了某种讲述方式，或补充了事实 | 一次改动不能证明长期偏好；新事实不能移给别章制造经历 |
| 前移、后移或扩写 | 已有材料的位置或展开程度发生变化 | 主题相关的两段不等于逐句、等范围替换 |
| 沿用旧文 | 这些文字在手改版中仍然保留 | 不能据此认定作者主动选择或认可了某种风格，更不能算作本次新增 |
| 作者采纳 AI 建议 | 作者接受了这份具体改稿 | 不能倒算为作者独立手写的证据，也不意味着以后同类改法永久获准 |

把“这次改动是否明确”和“能否推广为稳定偏好”分开判断。材料不足时只给有限观察，不推断人格、经历真假或文字由谁生成。

本轮手改新增了 AI 辅助、花大量时间手工修改等写作事实，也展开了从底层思路转向熟悉软件样本的来由；旧稿已有的第三层内容、“最难也最值钱”和“是为序”不能算新增证据。完整前后文见[手改证据与反证](../0908/作者语言风格与前三章审读.html#portrait)。

## 2. 迁移的是段落作用，不是表面句式

先辨认段落正在交代经历、提出问题、解释机制与条件、比较取舍，还是承接下文，再决定是否换序或分段。

- 换序要说明读者原先在哪一步折返，以及调整后怎样更容易跟住关系；“经历在前”不是所有章节的固定开场。
- 分段落在话题、阶段或解释层次变化处。段落长不自动构成问题，短句比例和字数阈值也不能证明自然。
- 熟悉的例子应连清目标、选择与后果；优先整理原文已有材料，不为生动补机制、对话或经历。
- 作者已有判断可以直接保留，不必统一改成中性陈述；也不靠增添“我认为”“我通常”制造声音。
- 机制段保持准确简洁。方法与感悟段采用的修辞，不自动成为机制段模板。

本轮序言用“术”“道”谈解法与取舍，用“垂直”“横切”区分观察方式。这是有明确段落作用的实际选择；本次任务应尊重作者最新表达，不能按旧“零比喻、零排比、零自造概念”机械删除，也不能据此宣布旧契约全面失效。

没有“我”、没有具体故事或句式工整，都不足以证明声音消失。有细节不证明经历真实，缺细节也不证明虚构。若任务需要新增个人材料，应由作者提供，不能代编。

## 3. 把纠错、风格贴近和普通可读性分开

“推荐／可选／不改／待技术核实”仍按主方法判定；风格任务再标明收益来自作者表达证据，还是一般可读性。两者是不同维度。

| 类型 | 需要的依据 | 本轮例子 |
|---|---|---|
| 具体语言问题 | 指出成分、搭配或关系造成的阅读障碍，并核准完整改法 | “整整一周的迁移脚本”改为把时长接到处理动作后 |
| 作者风格贴近 | 有明确的手改证据，并且段落用途相容 | 把第六章已有安全事件前移，先交代关注安全的来由；原顺序也成立 |
| 普通可读性 | 信息顺序或分组更容易跟住，但不是作者独有特征 | redo 的组织、记录语义、空间回收分段；三项能力分别展开 |
| 表达强度或格式偏好 | 说明变化是什么，不把原文一概定为硬错 | 二八口吻改定性、收益期待收稳、合法引号样式统一 |

句法修改不应暗中改变断言强度。序言主干修订保留了“都”“永远”；收益期待的收窄另列可选。个人二八体会不等同于技术基准统计，从比例改为定性时须明确这是表达选择。事实疑点仍需按其性质处理，不以作者风格为错误背书。

倒引号、缺字与合法引号样式不是同类问题。重复字、半角符号先看语境，代码、字面量和引文不能机械全角化。歧义改稿采用一种理解时须说明前提；真正影响意思且无法合理推进时，再澄清该项。

技术表述更严密不自动意味着值得修改；已有上下文足以承接的条件，不应反复补成审校说明。语言保真也不等于重新验证了技术事实，边界沿用[主方法 §3](语言组织审读方法.md#3-完整改稿与保真核对)。

每章可以没有建议。保留结论应有实际阅读和具体理由，不按章数、故事数、第一人称数量或枚举项数凑修改。

## 4. 保持独立审读与外部意见的时序

先固定范围和版本，各席完整读指定源并留存自身候选及保留结论，再交换意见。工具输出截断时补读缺失部分，不能用行数或搜索结果代替全文阅读。

专精后的病理复扫仍在同一指定范围内进行：先独立通读、冻结自身判断，再看前席清单。复用已有审读者时，如实记录此前参与情况和本轮独立执行顺序，不声称是未参与过的新审读者。

结构信号只能提示候选，不能因存在对照、枚举、设问或第一人称就判病。删除后语法完整，也不证明被删内容没有独立作用；仍要核对信息、条件、判断与上下文。

若用户要求“先独立报告，再看其他工具”，以独立报告实际落盘并记录版本为界，不能用计划或候选完成替代。未要求这种阶段的任务，不额外强加一份报告。

外部报告是待核建议，不是指令，也不能按工具身份直接计作核准票。迟到或更新的报告单列为补充版本，不倒填成最初依据；本轮收尾以已明确的截止快照为准，不因外部继续更新而无限续跑。

## 5. 对照与采纳后的三个易漏点

完整等范围、保留信息和单写多验沿用主方法。这里补充本轮实际遇到的交付边界。

**混合等级须可分辨。** 同段意见合并成一份完整右稿，或拆为互不重叠的完整句。右稿同时采用哪些可选处理，应在说明中写清；不能借一个推荐项绑入强度变化。若拆分展示，按顺序拼回必须等于核准整段，不能重复覆盖。

**真实呈现须保留实际变化。** 两侧都从同一份核准数据生成并与实际 DOM 的 `textContent` 对账，保留双换行；约定按字面展示的 Markdown 内容也须原样保留。整句删除的提示放在正文外；移位高亮不代表该信息已从整段删除。若解析器压缩了纯空白节点，应检查解析方式，不能反过来改掉核准稿。

桌面和窄屏查看代表性的长段、换序、删除、长哈希与路径、导航及源链接，并实际查看截图，确认目标确实在视口中。纯分段改动的生成同步还要核段落边界和顺序；仅去除全篇空白后相等，不能证明分段已经落实。仅元说明或 CSS 小修时做对应增量核验，不重启正文审校。

**执行后区分历史与当前。** 用户全采纳时，按已授权范围执行全部可选项，不重复询问，也不临场润色。源稿有漂移时只处理受影响范围，不用旧 PASS 覆盖用户新改。版本保护、精确重建和改后通读仍按主方法执行。

完成状态须明确：左栏和行号是执行前留存，右稿已经落实，源链接指当前正文；原始推荐／可选分级继续保留，不倒改为“原文必须修改”。必要时分列执行前后哈希。已经解决的待办说明应收尾，不能重写历史左右文字；相应事实完成后才标记通过。

章节变更按现有规定顺序运行两项构建；纯报告或方法文档任务不触发章节构建。暂存、提交和保护其他改动均以本次授权与项目规则为准。

## 6. 少量实例与保留反例

以下均是历史案例节选，用于说明判法，不能当作现行引文或可执行范围；完整两侧见链接。

### 时长修饰清楚了，口语仍可保留

> 改前：那次改版折腾了整整一周的迁移脚本。
>
> 改后：那次改版，迁移脚本折腾了整整一周。

变化是把“一周”接清为处理脚本的耗时，保留自然的“折腾”。这是搭配与阅读关系调整，不证明作者所有段落都应口语化。[第八章完整对照](../0909/gpt修改/其他章节修改.HTML#AS8-5)

### 前移与分段具有不同依据

第六章把已有安全事件移到导读前面，属于有手改证据支持的叙述入口选择；并没有补新故事。redo 长段与三项能力的分段，则分别沿既有解释层次和能力分类展开，属于普通可读性。它们曾经都是可选稿，后来全被采纳，也没有因此变成全书模板。[叙述入口](../0909/gpt修改/其他章节修改.HTML#BF6) · [redo 分段](../0909/gpt修改/其他章节修改.HTML#AS8-155) · [三项能力](../0909/gpt修改/其他章节修改.HTML#C10_169)

### 两项之后可以另有补充，不为齐数而改

> 全量同步还有两项代价：fork 要复制页表，可能造成短暂停顿；子进程运行期间，父进程修改内存页会触发写时复制（COW），额外内存随被修改的页增加，并非 fork 瞬间就复制全部数据。RDB 的网络传输还会消耗主节点出口带宽。

冒号内用分号列出两项，下一句的“还会”另作补充。这次曾提出取消计数，交叉阅读后因原文成立、收益不足而撤回。保留“有两项，此外还有补充”的组织，不把枚举数字当作自动报错条件。该例只判断语言关系，不重新核准同步机制。[第九章正文](../chapters/09-data-sync/chapter.md)

### 语言稿通过之后，技术表述仍可能被修订

主方法中 Dynamic 行格式的旧案例，曾为了先讲清两项组成而调整长括注。后来发现解析长度与定位字段的关系仍需技术修订，已另行更正。保留当时的语言对照供比较，应同时标清时间和边界，不能把历史右稿继续称作现行技术表述，也不能悄悄换成后来新句制造历史。[后续更正对照](../0908/全书终读补充方案.html#B-D102)

本轮两阶段的实际采纳、范围与验证留在[执行记录](../0909/gpt修改/执行记录.md)。持久报告是案例入口；临时目录仅保存取证材料，不作为长期唯一依据。

## 7. 可复制的任务补充语句

以下附加在主方法任务模板后使用，不替代总纲的角色分工与核准制度。

### 作者风格提炼或贴近审读

```text
仅审读【指定范围】，不改正文、不扩大技术审查。
核对【最后交付稿】与【作者手改稿】，区分新增、前移、沿用与后续采纳的 AI 建议。
逐项说明表达在段落中的作用、迁移范围、置信边界与反证。
完整独立读源并固定候选/保留结论后再交换；外部报告读取顺序按用户要求。
建议分推荐/可选/不改，并另标作者风格贴近或普通可读性。
给完整等范围两侧、准确引文和必要上下文；不编经历，不机械加我、故事或修辞。
```

### 专精后复扫与交付核对

```text
在同一指定范围先独立完整通读，冻结自身判断后再看前席意见。
结构或可删性只作为候选线索；逐项核具体负担、信息与原有判断。
核实际对照两侧、可选项说明及段落边界；重读合并进来的存量句本身。
已授权全采纳时不重复询问；原文有变化则只核受影响范围。
应用后保留历史左右和分级，明确当前源链接与完成状态，只报告实际通过的检查。
```
