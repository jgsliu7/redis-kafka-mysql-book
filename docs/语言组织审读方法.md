# 语言组织审读方法

本方法用于用户指定章节或段落的语言组织检查：解释读者为什么需要停顿、补词或回读，再给出保留原意的改法。它不判断文字由谁生成，也不以句长、短句比例、CV 或关键词数量作为语病、自然程度或 AI 来源的判据。不因一次局部任务自动发起全书扫描。

正式章节以 [book-bible.md](book-bible.md)、[style-guide.md](style-guide.md) 为写作契约。多人独立判断、核对席逐字核引文、单人修改与多人复核，沿用 [AGENTS.md](../AGENTS.md) §4、§6 的现有制度；本方法只细化诊断和交付，不另设一套审批流程。

涉及作者手改提炼或风格建议时，另读 [作者风格保真审读经验](作者风格保真审读经验.md)，区分作者表达证据与普通可读性，并核对独立审读时序、混合可选项及应用后的历史状态。四维诊断、完整改稿与执行仍按本方法进行。

逐章阅读中怎样从理解形成候选，见 [§8 逐章审读中怎样发现问题](#8-逐章审读中怎样发现问题)；它细化四维检查，不增加自动扫描范围。

## 1. 四个检查维度

| 维度 | 具体问法 | 需要找出的证据 |
|---|---|---|
| 成分 | 谁对什么做了什么？句子是在陈述关系，还是只列出几个词？ | 缺少的谓语、宾语或必要限定，以及读者被迫补出的关系。 |
| 搭配 | 动词、宾语、数量和修饰对象配得上吗？这个数量究竟在数什么？ | 搭配错位的位置；不能只因表达抽象或不常见就判错。 |
| 顺序 | 基本意思是否先讲完整？补充说明是否隔断主干？总结后是否又补出尚未交代的条件？ | 插入、前置、后置分别增加了什么阅读负担；移动后哪些指代或图文关系需要重接。 |
| 关系 | 并列、因果、转折、递进是否准确？同一个连接词能否分别接到每一项上？ | 每个分句真实表达的关系；不能按连接词重复次数或并列项数量判病。 |

先顺着上下文读，定位实际卡顿，再用四维解释。长句、短句、括号、对照和口语都可以成立；修改对象是具体阅读障碍，不是某种句式的所有出现。

## 2. 把诊断和改法分开判断

每项意见分别回答两个问题：**是否认可诊断？是否认可这份具体改稿？** 诊断成立，改稿仍可能漏条件、换因果或制造新的模板。不能因为某工具标了“双票”就跳过原文核对，也不能因为改稿更短就认定更好。

| 结论 | 含义与交付 |
|---|---|
| 推荐 | 有具体阅读障碍，且改稿通过等范围、信息与上下文核对，可进入核准清单。 |
| 可选 | 原文能够成立，精简或换序主要取决于作者偏好；说明收益与取舍。用户已明确授权整份方案时按授权范围执行，不再次询问。 |
| 不改 | 诊断证据不足，或现有表达承担了必要关系。记录保留理由，作为防止误判的反例。 |
| 待技术核实 | 修改需要决定原文尚不明确的技术范围，或原有断言本身有疑点。本轮只处理已核准的语言部分，不顺带作技术修订。 |

诊断可以部分认可，改法也可以部分认可。最终执行清单必须标明具体采用的文字；同一段来自多个工具的意见合并成一份完整稿，避免局部建议互相覆盖。

## 3. 完整改稿与保真核对

每项交付包含位置、版本或哈希、逐字原文、完整改文、卡顿原因、修改范围、来源、两个独立判断和最终结论。历史引文须注明“改前留存”，不能用旧行号冒充现行原文。

原文与改文必须覆盖同一范围。局部教学摘录应明确标注；可执行稿必须保留该范围内未改的存量句，不能用省略号或“其余不变”替代完整文字。原报告若标“示意”，先补齐并核对，才可转为执行稿。

核对时逐项对账：

- 对象与动作：主语、操作对象、先后过程、并列项是否仍对应。
- 信息与限定：参数、数字、单位、复杂度、概率、版本、触发条件、适用场景和例外是否全部保留。
- 断言强度：平均与最坏、大概率与必然、可以与必须、局部与全部、有条件与无条件不能互换；原有未核实断言原样保留时须说明本轮没有作新背书。
- 技术字面量：术语、命令、类型名、前缀、长度、转义字节与配置名逐字核对。
- 删除与重排：删的是重复表述还是独立信息？后移的类比还指向原来的对象吗？重读合并进来的存量句本身，并检查段前段后、图注与图前图后文字。

“原文未丢信息”与“原文技术事实已重新验证”是两种结论。需要新增技术判断时，单列问题和依据；不得借语言修改默默改变范围。

若同时交付 Markdown 与 HTML，应从同一份文本数据生成。逐项核对两份的可见原文、完整改文与说明；左右对照中的删除、新增高亮要能还原两侧全文。移动的文字另注，不能让删除高亮暗示该信息已被丢弃。文件写完后再核对实际文件，不能只相信生成脚本或说明文字。

正文执行必须遵守 AGENTS.md 的单人修改、多席复核要求。任何 `chapters/` 下 Markdown 被修改后，运行 `python3 scripts/build_html.py` 和 `python3 scripts/build_pages.py` 两项构建；保护已有用户改动，暂存与提交按本次授权和项目要求处理，不扩大路径。不修改章节的分析文档任务不触发全书构建。

## 4. 第二章的四个已接受案例

以下记录来自 2026-09-08 第二章审读。[综合修改方案](../0908/第二章/综合修改方案.md) 保存改前与完整改后；这些旧句已经修改，不是现行原文。下列仅节选造成卡顿的部分，供说明方法，不能代替完整执行清单。本节及下文案例的“改后”与行号均指 2026-09-08 该轮审读留存版本，不代表现行正文；后续引用须重新逐字核对。

### 4.1 成分：补全复杂度关系

改前节选（方案 A2，原第 41 行）：

> 平均 O(log N) 的查找、插入、删除；

当时改后节选（该轮第 45 行）：

> 查找、插入和删除的平均时间复杂度都是 O(log N)。

原句是名词词组，读者需要补出“这些操作的平均时间复杂度是多少”。补全谓语时保留“平均”，没有改成无条件的复杂度保证。

### 4.2 搭配：一次计量的是解析动作

改前第一分句（方案 A8，原第 201 行）：

> 预编译把解析成本压到一次，

当时改后对应句（该轮第 213 行）：

> 同一条预编译语句反复执行时，解析只需做一次。

“一次”计量动作次数，不能直接计量成本。改稿同时补回同一预编译语句反复执行的范围。原段“二进制结果集把传输体积压到最紧”仍在，方案已注明没有重新验证“最紧”的比较范围。

### 4.3 顺序：先完成 A 和 B，再解释 A

改前节选（方案 A5，原第 92 行）：

> 以默认的 Dynamic 行格式为例：行头存变长字段长度列表（字段长度倒着排、解析指针从右往左走，每读到一个长度就恰好落在下一个字段的边界上，一趟扫完）和 NULL 位图，后面是各列数据。

当时改后两句（该轮第 102 行，非现行技术表述）：

> 以默认的 Dynamic 行格式为例，行头存变长字段长度列表和 NULL 位图，后面是各列数据。长度列表中的字段长度倒着排，解析指针从右往左走；每读到一个长度，就恰好落在下一个字段的边界上，一趟即可扫完。

长括注隔开了“长度列表”和“NULL 位图”。当时的改稿先说明组成，再讲解析；倒序、方向、边界和一趟扫描均保留，“恰好”也没有机械删除。

本例保留该轮语言改稿供比较；同段后续已作[技术修订](../0908/全书终读补充方案.html#B-D102)，现行机制以第二章正文为准。此处的保留核对仅指当时信息对应，不构成对旧解析描述的技术背书。

### 4.4 关系：拆开不同理由

改前节选（方案 A7，原第 197 行）：

> Redis 要快，所以 SDS 取长 O(1)、字典做渐进式 rehash、跳表在缓存局部性上付出了代价，换来实现的简洁。

当时改后对应两句（该轮第 209 行）：

> Redis 要快，所以 SDS 取长度的时间复杂度是 O(1)，字典做渐进式 rehash。跳表在缓存局部性上付出了代价，换来实现的简洁。

前两项回应“要快”，第三项说明实现简洁与缓存局部性的取舍。拆开共同因果，三项内容全部保留；同段 MySQL、Kafka 的存量句没有删掉。

## 5. 三个防止误判的反例

以下原句在该轮审读中保留，出处均为 [第二章正文](../chapters/02-data-structures-protocols/chapter.md)。这里只判断对应语言诊断，不对所在段全部技术事实作新背书。

1. **抽象范围可以用“里”。**该轮第 58 行节选：“把省不掉的工作分摊到后续每次操作里”。[DeepSeek 报告](../0908/第二章/deepseek修改意见.md) §1.5、报告第 78 行以“操作是事件不是容器”为由建议改成“操作上”。这里的“里”表达操作过程中的范围，不能套用实体容器规则判错。“上”可以是另一个表达选择，不证明“里”有病。
2. **两次转折可能分别成立。**该轮第 146、148 行开头分别是“但简单也有代价。”与“但 RESP 的"简单"恰好匹配了 Redis 的核心目标。”DeepSeek §1.8、报告第 110 行认为第二个“但”不是转折。上下文实际先由简单的好处转向代价，再由代价转向目标约束下的适用性；不能按重复次数删连接词。
3. **有内容的并列映射可以对称。**该轮第 177 行图注节选：“文本行换的是人眼可读与实现简单，二进制省的是带宽与解析开销，版本化请求头保的是演进兼容。”DeepSeek §2.7 与 [GLM 报告](../0908/第二章/glm修改意见.md) §3.3 均建议打散。三项分别承载不同对象和收益，不能只因“换的是／省的是／保的是”同构就判为无效排比。

## 6. 两个诊断可取、改稿不能照搬的案例

### 6.1 精简 Batch 表述时丢了条件

DeepSeek §1.7、报告第 94 行的原文栏节选：

> 生产者会把消息积累成一批（攒够 `batch.size` 字节，或等到 `linger.ms` 毫秒）再打成一个 Batch 发到 Broker

该报告建议栏：

> 生产者会把消息攒够一批，再打成 Batch 发到 Broker

即使认可“积累成一批”和“打成一个 Batch”有精简空间，这份改稿仍删除了两个参数及“或等到”的条件关系，不能整句采用。该轮改后第 110 行保留了原条件。本例核对的是文字删漏，不另作机制审查。

### 6.2 说明声称保留，实际示意稿却遗漏

[GLM HTML](../0908/第二章/glm修改意见.html) 第 239–241 行提供原第 41 行跳表段的“改后 · 示意（拆 3 段）”。第 244 行说明原文为：

> 分号清单拆掉，复杂度各自跟对应的操作走。"平均 O(log N) 的查找、插入、删除"中"查找"复杂度并入段二"树高大概率落在 O(log N)"口径（示意稿口径以技术席核对为准）。

实际三段没有查找、插入、删除的平均复杂度，也没有声称已并入的“树高大概率落在 O(log N)”。保留了其他操作的复杂度，不能抵消这两处遗漏。MD §2.3 只提出拆段方向，没有这份具体重写；不能把 MD 的方向认可等同于 HTML 稿通过。示意稿必须补齐并逐项核对后才可执行。

## 8. 逐章审读中怎样发现问题

以下归纳来自 2026-09-08 至 09 日逐章报告，补充从连续理解到形成候选的具体动作；四维诊断、分级与保真仍按 §1–3。这些是读时的问题，不是七种新病理，也不是每段必填的表或每章必须命中的清单。

先用一句话说清本段正在回答什么：机制怎样运行、为什么这样设计、代价是什么，还是把前文收成判断。再看下一句是继续解释、补条件、举例，还是换了问题。换题本身正常；只有思路未收完就转入另一条，或读者需要回找对象和条件时，才形成候选。

本节案例均为当轮历史对照或保留理由，不是现行正文的错误清单；局部节选不能再次直接执行。独立报告用于辨认当时发现了什么，综合报告用于确认最终采用了什么；语言项中未改的技术断言不因此获得本次重新核准。完整范围及后续变化以所链接报告为准，逐章覆盖与执行历史见[总记录](../0908/优化执行记录.md)。

### 8.1 将共享动作和省略对象逐项还原

遇到并列、把字句、两种后果或一串操作，先在笔记中将每项还原为“谁—做什么—对什么”，把共用谓语分别接回每项。若后项换了对象或动作，补明缺失关系，不先删并列。遇到“这、前者、各自”等回指或省略对象时，先查本句前后已经给出的定义与动作；不能只选最近的名词，也不能凭技术常识替作者猜对象。

历史例：第三章“这些清理工作要么留给下次启动补做，要么变成永久丢失”，后半实际指数据丢失；当轮分别写成留待补做和造成数据永久丢失，保留退出条件与两种后果。[R1 完整对照](../0908/第三章/综合修改方案.html#R1) 第六章“启用状态”补为“将其启用”，对象来自同句创建的用户。[R48 完整对照](../0908/第六章/综合修改方案.html#R48)

停止边界：名词式标题、标签、已有总领谓语的清单可以成立；原省略能顺读时，补全只列可选。存在不同合理理解时说明采用的前提；需先决定机制范围才知对象的，按 §2 转为待技术核实。

### 8.2 沿解释对象寻找插语的进入点和返回点

标出原段依次解释哪个对象、作用、实现和成立条件。暂时越过插语读主线，再将每条版本、参数、例外和出处挂回准确对象，重点找三类折返：共同主干未完成就进入某一项的细节；条件还未交代完就先总结；原因隔着另一对象的对照才出现。必要时调整顺序，不能把临时跳过的内容当作可删信息。

历史例：第五章先完成 THD 对象、连接状态与跨层用途，再保留缩写展开并无权威定义的说明；对象用途与缩写出处属于不同层次。[F1 完整对照](../0908/第五章/综合修改方案.html#F1) 第六章先闭合密码以摘要保存、不存明文的主句，再说文件保存、重读与覆盖；“这是凭证落盘的最小安全要求”的回指也随主句保持，不让它误指文件覆盖。[R50 完整对照](../0908/第六章/综合修改方案.html#R50)

停止边界：不规定所有段落都先原因后机制，也不把括注统一移到段末。条件若正限制紧随的操作，就应保持邻接；信息密但依赖顺序清楚，不需为缩短主句拆碎。

### 8.3 核比较两端、计量对象与得失方向

遇到“更、高、低、达到、代价、换来”等表述，分别写出两端对象、比较指标和方向：计量的是动作次数、对象数量还是耗时？被增加的是收益还是工作？表头是否覆盖实际单位？成本与收益是否被同一谓语混成一类？先定位关系，再决定修搭配还是转交技术核实，不靠换形容词掩盖量纲或范围问题。

历史例：第四章表中既有延迟也有 MB/s、GB/s 的吞吐量，表头不能全部称为访问延迟；当轮只校分类标签，未重算各行数字。[R2 完整对照](../0908/第四章/综合修改方案.html#R2) 第五章“这笔开销就是生态收益”改为“这笔开销换来的是生态收益”，补的是交换关系，作者判断仍保留。[F3 完整对照](../0908/第五章/综合修改方案.html#F3)

停止边界：合法的“用 A 换 B”不必删除。若比较必须重新判断负载、版本、实现或测量口径才能成立，不能只调字词就称已修好；正常近似也不自动等于最坏保证。

### 8.4 核小连接词新增了什么逻辑承诺

既要检查原句的共用连接词，也要检查改稿新加的关系。“同时”改“再”可能新增先后，“除了”或“此外”可能引入互不包含，“因为、所以”可能新增因果，“只、只有”可能收窄用途；计数式总领也可能把局部列举变成穷尽。将这些承诺逐项与上下文对照，只有关系已经建立时才加入。单纯话题转换，换段本身可能就够了。

历史例：第五章三个验收问题之后转入请求路径，当轮补了段落边界，没有新写两话题间的推导句。[N19-20 完整对照](../0908/第五章/综合修改方案.html#N19-20)

停止边界：不能为了“接得顺”添加原文没有的先后、排除、因果或唯一用途；分别成立的转折与并列也不按出现次数删去。两个分句能连在一起，不证明它们具有推导关系。

### 8.5 按信息用途判断承接与重复

读到“新、又、这些、同样、这一点”时，回看前面究竟已说过什么。比较的是信息和功能，而不是重复字串：后句是在同义复述，还是由定义转后果、由公式转预算、由案例转判断？合并多份改稿后也逐句问新增了什么；只有没有独立条件、对象、判断或必要呼应可保留时，才提出删除。

历史例：第七章写扩展与单机容量在前文已存在，不能统称为“新局限”；当轮改成“还有三个局限”，保留后续问题分工。[N71 完整对照](../0908/第七章/综合修改方案.html#N71) 第五章合并后的段尾再次说类型语义保持、内部适配，终读只删重复尾句，版本、编码、复杂度与实例保留。[B-E69 完整对照](../0908/全书终读补充方案.html#B-E69)

停止边界：删除后语法完整不证明信息无损。第九章保留窗口与净追赶速度分别回答数据是否还在、能否追上，虽都谈追赶，也不能当作重复；当轮保留了定义、条件、公式和例子的连续解释。[保留例](../0908/第九章/gpt修改意见.html#good)

### 8.6 沿同一主张核正文与收束的范围

在指定范围读到一个主张再次出现时，先判断两处是否真的说同一件事，再比对象、分类维度、条件与强度。同一信息进入小结、表格、图注或书目附注后，是否漏掉已经讲过的分支，或把局部范围扩大了？只沿本轮已知主张的直接复用处核对，不自动扩扫所有章节或开启另一轮技术审计。

历史例：第五章已列队列交接、对象调用和网络协议，末句却把单机内一律收成对象调用；当轮补回本段已有的队列分支。[F6 完整对照](../0908/第五章/综合修改方案.html#F6) 参考文献的 CAP 附注后来随正文讨论范围同步，这属于引用说明与正文对应，不是判原论文有事实错误。[SW6 完整对照](../0908/全书终读补充方案.html#SW6)

停止边界：分类不一致之前先核维度。第八章明确区分主存储位置与落盘文件组织，两个视角允许不同分类，不需统一成一组标签；五条启示与四种取舍也不因数字不同自动冲突。[第八章当轮保留例](../0908/第八章/gpt修改意见.html#good)

### 8.7 在需要选择机制解释的地方分流，并明确停止条件

补对象、移动条件或换动词若能由同段直接确定，可形成保真的语言候选；若必须决定实际执行阶段、默认值、保证或因果，先单列该主张需要的依据。不能靠删“天然、一定”而留下同一错误推导，也不能用更多技术细节代替修改必要性判断。已能确认的语言问题与待核机制分别记录，不互相冒充通过。

历史例：第四章的最坏丢失窗口涉及刷盘进度，不能仅凭顺句修好；当轮依据核实后，正文正面写“后台刷盘受阻时，实际丢失窗口可能更长”，对旧阈值的反驳留在报告。[B-F101 完整对照](../0908/全书终读补充方案.html#B-F101) 同轮保留“约 1–2 秒量级”的近似表达，未把它当最坏上界，也未在摘要反复补故障条件。[保留决定](../0908/全书终读补充方案.html)

停止边界：本节不授权额外技术研究。需要核实的范围按 §2 单列；已由邻接条件或基线覆盖的合理省略、正常近似及有据判断可以保留。每个候选最终应说清读者原先需要补哪一层关系；若收益仅是更短、更齐或换一种偏好，列可选或不改。
