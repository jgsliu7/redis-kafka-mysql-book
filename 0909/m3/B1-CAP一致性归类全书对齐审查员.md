## 4. 全书统一口径建议（具体话术样板）

### 4.1 确立全书统一立场（ch7 正文已具备，可直接推广）

> **Redis Cluster**：默认异步复制，分区时少数派主节点在 `cluster-node-timeout` 后停止写入；已确认写入在故障转移时可能丢失。社区对其 CAP 归类有争议，本书不作绝对归类。与其贴 AP 标签，不如关注"何时停写、已确认写入能否保留"。

> **MySQL**：提供异步复制（不等副本）、半同步（等 1 个副本 ACK，超时降级）、MGR（等多数派确认）三种选项，默认异步复制。不同选项的确认条件、故障转移保留和等待开销各不相同，不能用一个 AP 或 CP 标签概括。

> **Kafka**：把确认范围做成 `acks` 参数，默认等待 ISR 全部副本确认（acks=all），并由 `min.insync.replicas` 控制最低 ISR 数量。`unclean.leader.election.enable` 控制 ISR 全挂时是否允许落后副本当选。这些旋钮让使用者按场景选择，而非系统自带固定立场。

### 4.2 统一口径话术样板（可直接替换 outline 中的绝对归类）

| 场景 | 禁止用语 | 替换为 |
|------|---------|-------|
| Redis 集群归类 | "Redis 选 AP" / "Redis 是 AP 系统" / "AP 取舍" | "Redis 默认异步复制，分区时优先保持可用，代价是已确认写入可能丢失——社区对其 CAP 归类有争议" |
| MySQL MGR 归类 | "MySQL 选 CP" / "MySQL 是 CP 系统" / "CP 路线" | "MySQL MGR 在提交前等多数派确认，分区时少数派停止写入；默认异步复制则不等副本，需分别判断" |
| Kafka 归类 | "Kafka 在 AP 与 CP 之间可调"（暗示 AP/CP 是两种固定状态） | "Kafka 把确认范围做成参数，使用者按场景配置；默认值等待 ISR 全部副本确认" |
| 一致性模型列 | "异步最终（AP）/ 多数派强一致（CP）" | "默认异步复制（不等副本）/ 可配置等待确认（含多数派）/ acks 参数可调" |
| unclean leader | "经典 CAP 取舍的显式开关" | "在'等待合格副本恢复（可能短时不可用）'与'接受落后日志（可能丢数据）'之间切换" |

### 4.3 表 9-1（大纲版）CAP 列修订建议

将 outline.md L74 的"一致性模型"列：
- ~~异步最终（AP）~~ → **默认异步（不等副本确认）**
- ~~异步/半同步/多数派强一致（CP）~~ → **可选：不等/等 ACK/等多数派**
- ~~ISR+acks 可调（AP↔CP）~~ → **acks 参数可调，默认等 ISR 全部确认**
