## 2. 混用问题清单（含具体行号）

### P0 — 同一段内乱跳，读者立刻混淆

**P0-1｜quorum 未标注（ch7 L65）**
- 位置：`chapters/07-cluster/chapter.md` 第 65 行
- 原文：`配置的 quorum（quorum 是人工设定的判定票数，不必是多数派）`
- 问题：quorum 是缩写首现，且 book-bible §7 明确规定 `quorum → 多数派`，首次出现应标注为 `quorum（多数派）`，而非括号内又用"quorum"自释
- 修复建议：在 ch7 L65，将 `配置的 quorum（quorum 是人工设定的判定票数，不必是多数派）` → `配置的 quorum（多数派，人工设定的判定票数，不必是多数派）`

**P0-2｜epoch 未标注（ch7 L90）**
- 位置：`chapters/07-cluster/chapter.md` 第 90 行
- 原文：`epoch 用来区分选举和配置的新旧`
- 问题：epoch 与 book-bible §7 的 `epoch / term → 任期` 对应，首现直接用英文"epoch"而未标注中文"任期"。后续章节（ch9 L225、L231）已正确标注为 `leader epoch（单调递增的任期号）`，ch7 的首次出现反而缺失标注
- 修复建议：在 ch7 L90，将 `epoch 用来区分选举和配置的新旧` → `epoch（任期）用来区分选举和配置的新旧`

### P1 — 跨章不一致

**P1-1｜"从库/主库"与标准词"从节点/主节点"局部混用**
- 位置1：`chapters/03-lifecycle/chapter.md` 第 130 行
  - 原文：`从库要等复制线程退出。……主库关闭则直接断开 dump 线程……`
- 位置2：`chapters/09-data-sync/chapter.md` 第 179 行
  - 原文：`主库并发低会限制……`
- 问题：book-bible §7 规定 `follower / slave / secondary → 从节点`，`leader / master / primary → 主节点`，而这两处用了"从库/主库"。ch3 那句在说 MySQL 关闭场景（属于 MySQL 语境），ch9 那句在谈 MySQL 主库并发（也是 MySQL 语境），而 MySQL 语境在 8.0.26+ 已改称 source/replica。混用"从库/主库"既不符合 book-bible 标准词，又未体现 MySQL 8.0.26 术语更新
- 修复建议：
  - ch3 L130：将 `从库要等复制线程退出` → `从节点要等复制线程退出`；`主库关闭` → `主节点关闭`
  - ch9 L179：将 `主库并发低` → `主节点并发低`

**P1-2｜ch9 两票"quorum"均无标注**
- 位置1：`chapters/09-data-sync/chapter.md` 第 252 行
  - 原文：`由 Controller quorum 维护`
- 位置2：`chapters/07-cluster/chapter.md` 第 65 行（同 P0-1）
- 问题：ch9 L252 的"quorum"同样未标注；且在同一段落（ch9 §9.4 末）内既有参数语境（如 `unclean.leader.election.enable`）又有正文描述，上下文术语语言不统一
- 修复建议：ch9 L252 将 `由 Controller quorum 维护` → `由 Controller quorum（多数派）维护`

**P1-3｜"Flush List" 未加引号或标注，与 InnoDB 其他专有结构格式不一致**
- 位置：`chapters/04-memory-disk/chapter.md` 第 140 行
- 原文：`Flush List：脏页链表`
- 问题：ch4 中 InnoDB 其他专有结构均已加引号（如 `Infimum` / `Supremum`），"Flush List" 未加引号，格式不统一
- 修复建议：ch4 L140 将 `Flush List：` → `Flush List（脏页链表）：` 或 `**Flush List**：脏页链表`

**P1-4｜"epoch" 在 ch9 标注了但在同一段落内标注程度不均**
- 位置：`chapters/09-data-sync/chapter.md` 第 231 行
  - 原文：`Kafka 用 **leader epoch**（单调递增的任期号）标识日志的任期边界`
- 问题：ch9 L231 正确标注为 `leader epoch（任期号）`，但 ch9 L233 又回到 `"epoch 补充了 offset 所没有的历史信息"`，在同一章节内"epoch"一会出现标注、一会不标，形成内部不一致
- 修复建议：ch9 L233 将 `epoch 补充了 offset 所没有的历史信息：` → `epoch（任期）补充了 offset 所没有的历史信息：`

### P2 — 细微差异

**P2-1｜ch1 L202 缩写首现说明在章末而非首次出现位置**
- 位置：`chapters/01-introduction/chapter.md` 第 202 行
- 说明：全书术语约定说明（含 ISR、AOF、RDB 等首次出现应如何标注）写在第 1.4.3 节末段，是阅读约定而非正文中的首次使用标注。这在技术上合规（约定说明在 §1 末尾），但对于 ISR（ch1 L94 已出现）和 AOF（ch1 L165 首次出现）来说，约定说明文字出现在实际使用之后，阅读顺序上靠后
- 影响：轻度，约定文字放在章末而非章首，是结构性问题，非术语误用
- 建议：考虑将术语约定说明移至 1.4.3 节开头，或在 1.4.3 开头加一句"以下为本章及全书的术语使用约定"

**P2-2｜ch5 L185 "任期" 语境中偶现英文"epoch"**
- 位置：`chapters/05-layered-architecture/chapter.md` 第 185 行
- 原文：`Kafka 把存储做得极薄（就是追加写日志），索引、复制、**压实**的复杂度都在上层解决`
- 说明：此行实际上写的是"压实"，不是 epoch 问题。但 ch5 在描述 Kafka 存储时，与 ch8/ch9 中 Kafka "leader epoch" 的中文标注（ch9 L225）存在整体节奏差异：ch5 没有解释为什么要用 compaction/压实这个名字
- 影响：轻微

**P2-3｜"AOF/RDB" 在同一括号内未加空格**
- 位置：全书多处，如 `chapters/03-lifecycle/chapter.md` L46 `AOF/RDB`
- 说明：这是缩写连用形式，格式上可接受，不构成问题

**P2-4｜ch9 L161 "Redis 的 `min-replicas` 触发拒绝写入、Kafka 的 ISR 收缩虽然采取了不同动作"**
- 说明：此句中 ISR 用了缩写，但没有重新标注（ch1 已标注过，这是同章复用）。按 book-bible 约定，缩写首次标注后继续使用是正确做法——本条不是问题，是合规使用，记录以备确认

**P2-5｜ch3 L245 "AOF 刷完"——"刷"与"刷盘"选择**
- 位置：`chapters/03-lifecycle/chapter.md` 第 245 行
- 原文：`没等 AOF 刷完就杀了进程`
- 说明：book-bible 规定"flush → 刷盘（中文）"。此处用"刷完"而非"刷盘完"，但"刷完"是口语化表达，"刷"作为"刷盘"的省略在 ch3 语境（亲历段）中可以接受。建议保留，不作修改

**P2-6｜ch10 L86 "LSN" 未在第 10 章重新标注**
- 位置：`chapters/10-summary/chapter.md` 第 86 行
- 原文：`LSN 等运行时状态`
- 说明：LSN（Log Sequence Number）不在 book-bible §7 的 23 项核心术语中，属于扩展术语。第 10 章使用 LSN 但未展开缩写。第 4 章首次出现时是否标注了？（ch4 L155 未见 LSN 展开）。按 book-bible §7 末"遇未列术语，首次以'中文（英文）'标注"规则，LSN 应在首次出现处标注
- 影响：LSN 为 MySQL/InnoDB 领域常见缩写，未展开可能对非专业读者造成障碍
- 建议：确认 ch4 是否首次出现 LSN，如未展开则在第 4 章补注

**P2-7｜ch9 L315 "分区、offset 与 leader epoch 识别日志位置及任期" —— epoch/term 未统一**
- 位置：`chapters/09-data-sync/chapter.md` 第 315 行
- 原文：`Kafka 用分区、offset 与 leader epoch 识别日志位置及任期`
- 问题：ch9 L315 用了"epoch"和"任期"两个不同层次的名词，ch9 L231 已正确标注 leader epoch → 任期，但此句中 epoch 单独出现未附注，且"及任期"重复了 epoch 的中文翻译，显得冗余
- 修复建议：ch9 L315 将 `Kafka 用分区、offset 与 leader epoch 识别日志位置及任期` → `Kafka 用分区、offset 与 leader epoch（任期）识别日志位置`

**P2-8｜ch7 L98 MySQL 术语演进括注稍长**
- 位置：`chapters/07-cluster/chapter.md` 第 98 行
- 原文：`一台主节点（Master，8.0.22/8.0.23 起官方改称 source，新增 START REPLICA、CHANGE REPLICATION SOURCE TO 等语句别名）`
- 说明：括号内容较长，是 MySQL 8.0.26 术语更新的必要背景，但"新增 START REPLICA、CHANGE REPLICATION SOURCE TO 等语句别名"属细节，可考虑简化为"（8.0.22 起改称 source）"并移至括号后补充说明，或保留现有——此处是 P2，建议而非必须修改

## 5. 全书术语稳定建议

### 必须修复（P0 → P1 级别）

1. **在 ch7 L65 将 `quorum` 标注为 `quorum（多数派）`**
