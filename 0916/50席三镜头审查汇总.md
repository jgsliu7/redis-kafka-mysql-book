## 2. 席间分歧点（需裁决，优先级高于一切修复）

### D1（最高优先）：半同步 ACK 与 sync_relay_log 的关系

- **A10（判错）**：引 MySQL 8.0 手册原文 "The replica acknowledges receipt of a transaction's events only after the events have been written to its relay log **and flushed to disk**"，据此判 ch10:78「是否同步到磁盘还取决于副本的 `sync_relay_log`」为事实错误；改法：「副本把事务事件写入 relay log 并刷盘后才返回确认」。（注：A10 所引节号 §19.4.10 疑有误，MySQL 8.0 手册半同步节为 §17.4.10；但所引英文句子本身需一手核实。）
- **A09（判对）**：ch9 审查时明确记录「半同步 ACK 时机与 `sync_relay_log` 持久性区分」为**准确**。
- **现状**：ch9:157「副本 I/O 线程把事件写入 relay log 文件后即回 ACK」与 ch10:78 同族；若 A10 成立则两处都要动，若 A09 成立则 ch10:78 保留。**建议**：派一手核实席查手册原文 + 源码（`sync_relay_log` 在半同步路径是否被旁路），或由作者凭经验裁定。
- **2026-09-16 裁决：D1 闭合，现稿保留。** §7.4 证据 3 的四条 mysql-8.0.44 源码链接经总调度逐一复核属实（详见 §8）：半同步回调直接应答、无额外强制 fsync；relay log 同步绑定 sync_relaylog_period。手册概括句与实现细节有差异，不足以推翻现稿。A10#1 诊断撤回，ch10:78 与 ch9:157 均不动。

### D2：Redis 7.2 支持窗口（ch1:204）

- **0915 T10（判错）**：redis.io/about/releases 一手复核——官方政策只维持「上一 minor + 上一大版本线末端」两支，当前最新 8.8 → 维护窗口为 8.x 前一支 + 7.4，**7.2 不在**；页面自述 "guidelines rather than rules set in stone"。
- **A01（判对）**：联网核查后记录「Redis 7.2/7.4 安全维护至 2029-12」，L204 无误。
- **建议**：一手核实 redis.io 当前页面与安全策略页后裁决；若取 T10 侧，0915 对照表 #5 已备好改法（「7.4 分支仍列在官方支持范围内（官方政策仅维持最新版与此前的两支旧线）」）。
