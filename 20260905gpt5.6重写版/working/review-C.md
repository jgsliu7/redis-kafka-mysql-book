| 图 | 结论与可保留信息 | 重画必须满足的正文约束 |
|---|---|---|
| 5-1 | 保留命令分派与 client 上下文主题，重画执行关系 | 完整参数后分派/检查；对象访问发生在命令执行中；结果进入输出缓冲后发送。AOF/RDB 不画成每条命令执行完必经的同步第六步。避免固定“一次哈希”与所有网络处理同线程。 |
| 5-2 | 保留 type/encoding 区分 | 一个类型只支持适用编码；服务端类型操作仍需识别编码；quicklist 包含节点而非等于 listpack；Set 的 listpack 限定 7.2；不写“任一编码”“命令代码无需修改”。 |
| 5-3 | 保留 THD 关联会话/语句/事务 | 不把共享上下文等同没有解耦；不把 THD 创建必然排在完成认证之后；不暗示引擎绕过执行器直接返回客户端。用职责关联而非精确函数时序即可。 |
| 5-4 | 保留 SQL 层与引擎能力差异 | handler 与引擎级回调分开；不承诺换引擎语义不变；删“全文索引好”“数十种并存”及所有行操作固定一次调用的无条件结论。 |
| 5-5 | 保留 Acceptor/Processor/RequestChannel/Handler | 队列是交接点而非线程；响应回到相应网络处理；标明所画为一个监听器路径，避免全进程仅一个 Acceptor；删跨产品延迟/数量级比较与队列防全部内存问题的保证。 |
| 5-6 | 保留消费与复制复用日志读取能力 | 各自身份、可见性、进度、异常恢复分别维护；本地文件且条件满足才适用相应传输优化；不写固定两次拷贝/两次切换、无条件 sendfile、Fetch 返回通用 LEO 或“新增功能只改一处”。 |
| 5-7 | 保留三类职责对应 | 以同步调用、队列和跨进程通信标边，不设固定 4/4/5 层数，不按固定快/生态/吞吐产品角色评价。 |
| 6-1 | 保留安全责任分类 | TLS 可参与认证，授权可多次发生，审计记录选定事件；不画成所有请求共有且必经的固定步骤。存储加密另示介质和密钥范围。 |
| 6-2 | 保留监听器与连接来源 | 明确 Broker、Controller 或合并角色示例；不能在纯 Broker 图中画 Controller 接收元数据 Raft 复制。移除内网天然高信任及无条件三跳 TLS 断言；ACL 前缀不画成自动 glob；审计不承诺完整默认内核。 |
| 6-3 | 保留 AUTH 后逐操作授权示例 | 示例先列允许规则；命令/键/通道是不同资源约束；不把二维检查写成全部 Redis 7.x ACL；ACL LOG 记录拒绝等事件，非唯一、完整审计。 |
| 6-4 | 主题保留、结构重画 | 普通适用授权组合；程序权限另分支；partial revokes 明示启用与数据库范围。不能把程序接在列权限之后，不写命中一处即可满足任意语句全部权限，更不写整个鉴权 O(1)。 |
| 7-1 | 保留能力组合主题 | 移除强制三步升级路线和产品 CAP 标签；Sentinel 授权不等于数据日志 Raft；分片/副本/故障转移/元数据管理独立组合，不承诺百万分区或 ISR 无条件无损。 |
| 7-2 | 保留三节点槽范围及 MOVED/ASK 对照 | ASK 的触发场景应是源迁移节点不存在该键，不能写“key 未迁出仍返回 ASK”；先 ASKING 再本次命令，映射不因此永久替换。哈希标签条件应保留。 |
| 7-3 | 保留 binlog→接收→relay→应用 | 不画成“提交后才写 binlog”；一个或多个应用工作线程，接收不等于已应用；不承诺副本互不影响。 |
| 7-4 | 可保留副本放置的基本结构 | 同分区副本非同一瞬间完全一致；ISR 为动态资格；“落后超过 30 秒”若保留必须是显式配置示例，不能作普遍定义。 |
| 7-5 | 保留检测/资格/恢复分开 | Redis Cluster 不混入 Sentinel 的 priority/offset/runid 选候选流程；组复制区分多数派、应用进度和读取策略；Kafka KRaft 控制面与分区选举不同，不承诺 ISR 内选主总不丢、毫秒恢复或 Controller 无冗余。 |
